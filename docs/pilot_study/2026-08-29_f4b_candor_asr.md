# F4b：CANDOR 侧 ASR 归因——真实域转写质量与状态质量的关系

> **日期**：2026-08-29
> **动机**：GPT 评审指出"真实域上的 ASR 归因不完整"。F4 只在金标准侧
> （Behavior-SD）做了归因；F4b 在真实域（CANDOR）补上。
>
> **脚本**：`pilot_study/scripts/ari_f4b_candor_asr.py`；结果 `annotator/f4b_results.json`

---

## 1. 方法

- 159 个声道（80 个有 X2-Turn 转写的 CANDOR 会话）。
- WER = X2-Turn 转写 vs AWS audiophile 文本（子串对齐口径）。
  ⚠️ 参考文本本身是 AWS ASR——WER 实为**两个 ASR 的转写分歧**，
  是真实 WER 的带噪代理。
- 状态质量 = 帧级 p_bc AUC vs AWS BC 窗口（与 E4 同口径）。

## 2. 结果

| 指标 | 值 |
|---|---|
| 声道数 | 159 |
| WER 中位 | 0.607 |
| AUC 均值 | 0.631 |
| **Pearson r(WER, AUC)** | **+0.306（p=0.0001）** |

## 3. 裁决

1. **真实域上同样没有"ASR 拖累状态"的证据**：相关是**弱的正相关**
   （r=+0.31）——转写分歧越大的声道，状态质量反而略高。最可能的解释是
   **交互密度混杂**：说话越密集的会话，两个 ASR 的分歧越大（长转写），
   同时 BC 事件越多、AUC 估计越充分。方向与合成域（r=−0.27 n.s.）相反，
   但两者一致地支持同一结论：**状态头质量与 ASR 质量弱耦合**。
2. **注意参考噪声**：AWS 文本自身的错误被计入 WER，本实验的 WER 是分歧
   度量而非真实错误率——结论应表述为"状态质量对转写分歧不敏感"，
   而非"状态质量对 ASR 错误不敏感"（后者需要人工转写参考，即 F3 的
   副产品）。
3. **对论文的意义**：F4+F4b 合起来补上了 GPT 评审指出的缺口——两域
   证据一致，L3 标注器的状态层鲁棒性有了完整归因。
