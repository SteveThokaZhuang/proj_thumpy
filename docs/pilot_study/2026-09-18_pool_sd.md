## 1. 预登记（落盘时间 2026-09-18，**跑之前**）

### 1.0 先说清楚这个测量**不**回答什么

- **不回答**「哪几个会话/哪段录音造成了漂移」。批次是全 200 个 key 分层的，
  会话组成不是变量（见 §1.2）。
- **不回答**「换一批**录音**会怎样」。池子就是 `e4_raw` 里那 100 个会话，
  没有第二批录音可抽。
- **不回答** margin 端点。那是另一笔 GPU 开销（§5.13 已论证），本节不动它。

### 1.1 要问的问题

> **ΔF1 在「同构造、不重叠」的评估集之间的波动，是不是比项目自己的
> bootstrap `SE_chunk` 所说的更大？**

如果**不大**：现有 `SE_chunk` 是诚实的，`e4x` 的「线下」与「天花板 t=1.667」
就是站得住的（是**这批块**的性质，不是抽样假象），下一步只是「还要多少块」的算术题。

如果**大得多**：那么判据线 `2×SE_chunk` 本身就是低估的，
`e4`/`e4x` 的线上/线下之争是在**噪声比它自己承认的更大的**量上做的，
且 `ΔF1` 的点估计本身漂移 ±22%（§5.10 已实测）⇒ 任何 k_min 反解都没有意义。

### 1.2 设计

**抽 12 批 × 每批 400 块 = 4800 块新块**，用与 `e4`/`e4b` **完全相同的构造**
（`ari_g1_eval4_ids.py`）：

| 维度 | 取值 | 为什么 |
|---|---|---|
| 池 | `e4_raw` 全部会话 = **200 个 (session, ch) key** | 与 `e4x` 同池，测量才可比 |
| 排除 | `g1_ids`(2400) + `g1_eval2`(1600) + `g1_eval4x`(1600) | 不重用、不含已评过的音频 |
| 时间重叠 | 同 key 下 \|Δt\| < 10s 全丢 | 相邻块共享 50% 音频（旧集会漏这层） |
| 流行率 | **自然**（不要求块内含事件） | §3.3 的伪影就是「100% 正例集」造成的 |
| 取样 | 每 key 内先打散再**轮转**，每批 = **2 轮** = 每 key 2 块 | 分层；每批都铺满全部 200 个 key |
| 批与批 | **互不重叠**，同一份打散顺序的连续轮次 | 12 批合起来就是「接下来 24 轮」 |

**评估**：与 `e4x` 同一套 **14 个 adapter**（own10 / mixnorm × 7 种子：
42, 1234, 7, 2024, 3407, 31337, 55555）。**0 训练。**

**循环顺序**：外层 `(arm, seed)`、内层 `batch`；两卡按 `(arm, seed)` 奇偶分片。
⇒ 每个 adapter 连着跑完 12 批（≈1.9h），**每一批**都由 14 个 adapter 在
14 个**不同时刻**评过 ⇒ 评估时刻与批次身份**不混杂**
（这条是针对 §7.4f 那个「A/B 分组与节点+场次几乎完全重合」的坑）。

### 1.3 对照（零模型）—— **与设计同构的那一个**

⚠️ 项目历史口径的 `SE_chunk`（`g1_e4_analyze.boot_se`）是**对块做有放回简单随机
重抽（SRS）**，而评估集是**按 key 分层的**。分层方差**低于** SRS，
所以直接拿 SRS 当对照会**高估**应有的跨批 SD。

**已先量（0 GPU，`g1_pool_null_probe.py`，跑在本预登记之前）**：

| 集 | SRS 零模型 | **分层零模型** | 比 (b)/(a) |
|---|---|---|---|
| `e4x`（200 key × 8） | 0.00977 | **0.00913** | **0.934** |
| `e4`（200 key × 6） | 0.00973 | **0.00869** | **0.894** |
| `filt`（155 key × 1–5） | 0.01985 | **0.01784** | **0.899** |

⇒ **分层把零模型压低 7–11%**，三个集一致。**本节一律用分层零模型**，
SRS 只作为并报的历史对照。
（这是 memory `threshold-must-match-null-model` 的同族：**对照必须与设计同构**。）

**正式对照**：在**合并的 4800 块**上做**分层 bootstrap**，
每 key 重抽 `m = 2` 块（与一批同构），`B = 2000` 次 ⇒ `SE_null(400)`。
同样口径在 `k = 800 / 1600` 上取 `SE_null(k)`。

### 1.4 统计量与判据（**先写死**）

记第 `j` 批的 `ΔF1_j`（= 7 种子均值的 own10−mixnorm，定义只有一处：
`g1_e4_analyze.d_of`）。

```
SD_batch(400) = SD({ΔF1_j}, ddof=1)          # J=12, df=11
ρ = SD_batch(400) / SE_null(400)             # 主统计量
```

**主检验（单侧）**：H₀ = 「块在 key 内可交换（即 bootstrap 诚实）」。此时

```
(J−1)·ρ²  ~  χ²_{J−1}        J=12 ⇒ df=11
⇒ α=0.05 单侧: 拒绝 H₀ 当 (J−1)·ρ² > 19.68  ⟺  ρ > 1.337
```

**判读（三档，先写死）**：

| ρ̂ | 判读 |
|---|---|
| **≤ 1.3** | bootstrap **诚实**（在 12 批的分辨率内）。`e4x` 的线下、天花板 t=1.667 站得住；下一步是「还要多少块」的算术题，用 `SD_strat(k) = SD_batch(400)·√(400/k)` 反解。 |
| **1.3 – 2.0** | **灰区**。如实报 ρ̂ 与 CI，**不下二值判决**；并报两种 ρ 下各自反解出的 k_min。 |
| **≥ 2.0** | bootstrap **低估 ≥2×**。真实池间 SD(1600) ≳ 0.018，**与效应本身（+0.0163）同量级** ⇒ 判据线被系统性低估，`e4`/`e4x` 的线上/线下之争是在比它承认的更大的噪声上做的。 |

**并报（不算判据）**：
- `k = 800`（6 组，df=5）与 `k = 200`（把每批拆成两轮，24 组，df=23）的
  `SD_batch(k)/SE_null(k)` —— **在样本内检查 `1/√k` 标度是否成立**。
  若三个 k 的比值一致 ⇒ 外推到 1600 有依据；若随 k 增大 ⇒ bootstrap 的
  `1/√k` 本身错了，明写出来。
- 批序与 `ΔF1_j` 的相关（时间漂移检查）。
- SRS 零模型下的同一个 ρ（供与历史数字对齐）。

### 1.5 代价与止损

- 4800 块 × 14 adapter × ~1.44 s/块/rún ≈ **26.8 GPU·小时 ≈ 两卡 13.4 h**（估）。
- 建库（`ari_g1_prep_subset.py`，CPU）另需 ~1.6 h，与评估并行，可续跑。
- **可续跑**：每个 `(arm, seed, batch)` 一份产物，已存在即跳过。
- ⚠️ 外层是 `(arm, seed)` ⇒ **没跑完就没有整批**。若作业到期中断，
  退化方案是**用已完成的种子子集**（如 5/7）算 ΔF1 —— 种子噪声变大
  （`SE_seed` × √(7/5)），但池间 SD 仍可估。**这一点在开跑前就写明**。

### 1.6 两个分支其实**都**指向「未检出差异」

必须写清楚，免得结果出来被当成「翻案」或「证实」：

`ΔF1 = +0.0163` 这个**点估计本身**从未被确立 —— §5.5c 实测「连收缩本身都没被确立」
（t=−0.55, p=0.60）。所以无论 ρ 落在哪一档，**研究结论都是「未检出差异」**。

**这个测量改变的不是结论，是「值不值得再投入」**：

- ρ ≤ 1.3 ⇒ 「未检出」的原因是**规模不够**，且 k_min 可算（大概率在可行范围内）
  ⇒ 加块是一条**可能有效**的路。
- ρ ≥ 2.0 ⇒ 「未检出」的原因是**池间噪声本身就 ≥ 效应**，
  而 `ΔF1` 的点估计在嵌套集之间已经漂了 22% ⇒ **加块只是把同一个不确定性买得更精确**
  ⇒ 停止在这条线上投入。

### 2.3 诊断

**批序 × ΔF1**（时间混杂的代理；外层 `(arm, seed)`、内层 batch 的设计本应无趋势）：
`r = +0.258`（n=12），置换零模型 20000 次得 **p = 0.410** ⇒ ✅ 与无趋势相容。
（n=12 时 |r| 的 95% 分位约 **0.583** —— 不查零分布就把 0.26 读成「有趋势」会误报。）

**事件数 × ΔF1**（不在预登记内，只作解释）：每批事件数 9–21，`r = −0.433` ⇒ 无强关系。

### 2.4 「还要多少块」的反解 —— **它比字面看起来脆得多**

按 `SD_strat(k) = SD_batch(400)·√(400/k)` 外推，让「均值 > 2×SE」成立需
**k ≈ 654 块**。但这个反解**继承 ΔF1 点估计的全部噪声**：

| 点估计来源 | ΔF1 | 反解出的 k_min |
|---|---|---|
| e4c（本次，4800 块） | +0.0255 | ≈ 654 块 |
| e4（1200 块） | +0.0210 | ≈ 967 块 |
| e4x（1600 块） | +0.0163 | ≈ **1,606** 块 |

**k_min 在 650–1600 之间漂，换一个点估计就换一个答案。**
这正是 §5.13 已经写过的病（分母是近抵消之差，ΔF1 在**平方**里 ⇒
线性漂 22% 放大成 40%）。**所以 §2.4 不是判据，只是提醒「加块」这条路的天花板比想象的软。**

### 2.5 §1 里没写、结果逼出来的结构性发现：四个集**是一次连续抽取**

写 §2.6 之前必须先说这件事，否则扩展会被当成「又抽了 4 批」。

**先说不是新的**：§5.10 已经建立了 `e4x = e4 ∪ e4b`（轮转取样**前缀稳定**，
`--n-eval 1600` 的前 1200 块与 `g1_eval4_ids.txt` 逐位相同）。本节**不重报**那条。

**新的是**：`e4c` 不是「又抽了 12 批」，而是**同一次抽取的继续**（轮 9–32）。
`--used` 是累积的，所以四次调用串起来 = 一次 32 轮的顺序轮转。实测：

```
e4x[:1200] == e4        （逐字节相同）
e4x[1200:] == e4b       （逐字节相同）
e4c ∩ (e4 ∪ e4b) = ∅    （不是重叠，是接在后面）
```

⇒ 四个集是同一次 `--shuffle-seed 0` 轮转抽取的**连续切片**：

| 集 | 轮 | 每 key 块数 | 块数 | 评估时刻 |
|---|---|---|---|---|
| `e4` | 1–6 | 6 | 1200 | 09-18 02:57 |
| `e4b` | 7–8 | 2 | 400 | 09-18 13:20 |
| `e4x` = e4 ∪ e4b | 1–8 | 8 | 1600 | （复用） |
| `e4c` | 9–32 | 24 | 4800 | 09-19 09:41 |
| **合计** | **1–32** | — | **6400** | — |

🔴 **这改写了一条既有结论**：§5.10 记的「批间漂移 −0.0198」**不是两次独立抽取之间的漂移**，
而是「把第 7–8 轮加进去」的效应。在连续切片的框架下，它是一个**轮次效应**，
不是抽样漂移 —— 两者在图上看一样，含义不同。

### 2.7 方差分解：**批数买不到种子的精度** 🔑

这是本次最有用的一条。

16 批 × 7 种子 = 112 个「批 × 种子」格。两向随机效应
`d_bs = μ + a_b + c_s + e_bs` 分解：

| 源 | SD | 占比 | 含义 |
|---|---|---|---|
| 批间 `a` | 0.01515 | **34.6%** | 抽到哪 400 块 |
| 种子间 `c` | 0.01032 | **16.0%** | **效应本身**随训练种子的异质性（配对**消不掉**） |
| 残差 `e` | 0.01811 | **49.4%** | 种子 × 批的交互 |

**7 个种子在全部 16 批上是同一批种子** ⇒ 加批**一点也**缩不了 `c` 那一路。
所以：

| SE 口径 | 值 | t = ΔF1/SE |
|---|---|---|
| 只算块路 `SD_batch/√16` | 0.0042 | 5.64 ⚠️ **偏乐观** |
| **两路都算** | **0.0057** | **4.12** ← 报这个 |

池化 32 轮的 ΔF1 = **+0.0235 ± 0.0057**（95% CI [+0.0123, +0.0346]）。

✅ **分解的自洽自检**（会失败的那种）：模型对 `Var(批均值)` 的预测是
`σ_a² + σ_e²/7 = 0.0002295 + 0.0000469 = 0.0002764`，
实测 `SD_batch(400)² = 0.01662² = 0.0002763` —— **对到第四位**。
⇒ 三项的估计不是拟合出来的巧合。（对不上就说明模型写错了，不许往下判读。）

🔴 **与 §5.5c 的关系必须说清楚**：§5.5c 说「未确立」用的是 **e4x 一侧**的块 bootstrap
（t = 1.667）。这里 t = 4.12 **不是翻案** —— 差别在**用了几轮**（32 轮 vs 8 轮），
**不在**「种子更可信」。两句话不矛盾，但**结论强度不同**，不许互相引用。
（这一条正是 memory `permutation-test-covers-one-variance-source` 记的
「只重抽块漏掉种子 SE：19.9 → 合并 42.4」。）

⚠️ 残差占 49.4% 是**配对降噪的边界**：配对消掉了种子的**主效应**，
但消不掉「哪个种子在哪批块上占便宜」的交互项。同族证据：
`power-analysis-before-ablation-runs` 记的「同种子配对在观测空间消融里不降噪（r = −0.29）」。

### 2.8 加块的**硬地板** 🔑

§1.6 把下一步说成「还要多少块」的算术题，那句算术隐含 `SE(k) → 0`。
但 §2.7 的 `c` 项**不随 k 缩小**：

```
SE(k) = √( var_a·400/k  +  var_c/7  +  var_e·400/(7k) )
                          ^^^^^^^^^^^ 这一项是地板
```

| | |
|---|---|
| `SE(k→∞) → √(var_c/7)` | **0.00390** |
| 「均值 > 2×SE」**最多**能做到 | 2 × 0.00390 = **0.00780** |
| 实测池化 ΔF1 | **+0.0235** ⇒ ✅ **在地板之上** |
| 带地板的 k_min | ≈ **904 块** |
| 老算法（把地板当 0） | ≈ 804 块 ⇒ **系统性乐观** |

**结论：加块这条路走得通**（效应 0.0235 是地板 0.00780 的 3.0 倍），
但**不是无限走得通** —— 就算堆到无穷多块、无穷多会话，
判据也只能做到 0.00780。**若效应小于 0.0078，加块永远够不到**，这条要先算。

### 2.9 诚实清单（读数之后才知道的事）

**A. `g1_e4c_pool_sd.py` 出数之后改了四处**（都记在此，不藏）：

1. **轮序改从抽样时的 id 文件读**。`paired()` 返回的 `cids` 是 `sorted(...)`，
   同一个 key 的 24 块会连续排在一起 ⇒「前 200 个下标」不是一轮而是前几个会话。
   第一次运行就栽在这：断言报 `批 0 的轮 0 只覆盖 100/200 个 key`。
2. **聚合口径改成「并集算一次」**。第一版按**每轮**算 ΔF1 再平均，
   k=400 的自检当场报 `0.009194`(分组) vs `0.009308`(paired)、`0.013725` vs `0.013502`
   —— **差在第四位，肉眼一定放过**。F1 是比值，`ΔF1(A∪B) ≠ [ΔF1(A)+ΔF1(B)]/2`。
3. 自检的元组解包写错（`zip(vals, djs)` 写成三项）。
4. `json.dump` 写进了 `chi2` 分布对象而不是统计量（`TypeError`）。

**B. 已知缺陷（都不是「跑挂了」，是设计与记录层面的）**：

- **`e4c` 的 12 批不是独立抽取**（§2.5）—— 它们是同一次轮转的连续 24 轮，
  与 e4/e4b 同源。**J=12 的 ρ 因此只反映「轮次之间」的波动**，
  不覆盖「换一个候选池」的波动。这是本测量**最大的解释边界**。
- **分段之间的批 × 时刻混杂**（§2.6），故扩展只作佐证。
- **`SE_null_strat` 与经验批间 SD 的口径差**：分层 bootstrap 给 0.01845，
  而由 §2.7 反推的 `√(var_a + var_e/7) = 0.01662`。
  ⇒ 若把 ρ 的分子换成分解出来的 `σ_a = 0.01515`，则 ρ = **0.821**。
  **两种分子都 ≤1.3**，结论对这一选择稳健 —— 但这个 ~10% 的口径差**没有解释**，
  留作未决项。
- **k_min 仍是事前算术**，用的是同一批数据估出来的 ΔF1
  ⇒ 它是「如果真效应就是 0.0235」的推算，**不是**对已观测效应的检验。
- **驱动脚本的完成判据曾数错**（全局计数 vs 注释声称的按片计数），
  在 08:36:17 打出过一次假 `E4C_EVAL_INCOMPLETE`。**故意等跑完才修** ——
  改一个正在运行的 bash 脚本会破坏它的解析。
- **预登记 §1.5 的退化方案没用上**：168/168 全跑完，无中断，无需用种子子集。
- ⚠️ **`ΔF1` 不可按块子集分解**（§2.9 A2），本文件里所有「一组 ΔF1」都是并集口径。
  交叉验证：扩展脚本对 16 批并集给出 +0.0234，而 16 批**先算再平均**是 +0.0235；
  在 e4x 上这个差更大 —— 4 批并集 = **+0.0163**（与已发布的 e4x 逐位相同），
  而 4 批先算再平均 = **+0.0172**。**差 0.0009，是本文件里最大的口径差。**

### 2.10 加块还降不降 SE？—— 直接量（**2026-09-19 追加**）

§2.8 的地板算在一个**假设**上：`SE² = C/N + var_c/ns`，即「块抽样那一项按 1/N 缩」。
§2.7 曾给出一条**看着要推翻它**的线索：把 `var_a` 从 k=400 加到 k=800，
它只缩到 0.87×（纯噪声应 0.50×），而且 SE **反而不降反升**
（0.00606 → 0.00709）。若当真，加块这条路就废了。

**那个线索是假的。**但它假在哪里，值得记 —— 我先用 `var ∝ k^-p` 拟了个指数
（`g1_e4c_varscale.py`），得到 var_a 的 p̂ = 0.43，看着像「显著小于 1 ⇒ 块成簇」。
问题在于：三档 k 的 `df_b` 是 **23 / 11 / 5**，而 `var_a = (MS_b − MS_r)/ns` 是两个
χ² 之**差**，df_b=5 时相对 SD 约 60% ⇒ **p̂ 的误差棒宽到判读不了**。
（我第一版连 SE 公式都写错了，印出 ±3.19 —— 那个数不可用，已作废。）

**换一个不含标度假设的测法**（`g1_e4c_se_scaling.py`）：e4c 的 24 轮，每轮都覆盖全部
200 个 key。随机抽 N 轮 → 取并集 → 算一次 ΔF1 → 重复 600 次 → 取 SD。
这就是 `ΔF1` 在 200N 块时的**抽样 SD**，不经 ANOVA、不拟合任何指数。

| N（轮） | 块数 | SD（随机抽） | σ̂ 反解 |
|---|---|---|---|
| 3 | 600 | 0.01142 | 0.02070 |
| 6 | 1200 | 0.00730 | 0.02021 |
| 12 | 2400 | 0.00404 | 0.01938 |

σ̂ 由**有限总体公式** `SD(N) = σ·√((R−N)/(N(R−1)))` 反解。三档独立反解出
**同一个 σ̂ ≈ 0.0201，相对散布只有 6.5%** ⇒ 这正是「轮与轮可交换、无成簇」的定义。
**正交的次序检验**同向：轮级 ΔF1 的 lag-1 自相关 `r = +0.241`，置换 **p = 0.268** ⇒ 无次序结构。

> ⚠️ 第一版这里还印过「连续取 12 轮比随机抽更稳 ⇒ 成簇」。**那是假的**：
> 连续窗口**互相重叠**（13 个窗口从 24 轮里取），窗口间 SD 被人为压小。
> 重叠窗口的散布**不是**一个 SD 估计。已换成上面的 lag-1 检验。

> 🔴 **2026-09-19 晚：本节下面的表与结论已被 §3 取代。**
> 这里的 σ̂ 是用**轮转抽样**反解的，而轮转**每一轮都含全部 100 个会话** ⇒
> 会话构成在轮间恒定 ⇒ **会话那一项方差结构上不进这个 σ̂**。
> 把会话簇加进 bootstrap 后，地板从 0.00376 涨到 **≈0.0063**，t 上限从
> 6.8 掉到 **≈4.0**，而**现在的 t 是 2.87 不是 4.61**，`N*` 也已越过。
> **下面的数字不是错的（它们是对「轮间」那一层的正确刻画），但它们不是
> 「这个效应还能做到多准」的答案。** 读 §3。

**结论 —— §2.8 的地板公式成立，加块仍然有用，但收益递减：**（⚠️ 已被 §3 修订）

| N（轮） | 块数 | SE | t = ΔF1/SE |
|---|---|---|---|
| 24（现有） | 4,800 | 0.00557 | **4.61** |
| 48 | 9,600 | 0.00475 | 5.40 |
| 96 | 19,200 | 0.00429 | 5.98 |
| ∞ | — | → 0.00376（种子地板） | → **6.8** |

- **块抽样项 0.00410 仍大于地板 0.00376** ⇒ 现在加块**还有用**，不是浪费。
- **撞地板的位置 `N* = (σ̂/地板)² = 28.5 轮 ≈ 5,700 块`** —— 就在现有规模上方一点点。
  过了它，再加块基本是白加，**只能靠加种子**。
- 🔴 **上限是 t ≈ 6.8**：这个效应**永远**做不成「t > 7」的结论，
  因为种子的那一路（16.0%）是无量纲的、加什么都缩不掉。

**顺带一个 §5.13 的回响**：用这里的 σ̂ 重算 `e4x`（8 轮 / 1600 块），
`SE = √(0.0201²/8 + 0.00376²) = 0.00804` ⇒ `t = 0.0163/0.00804 = 2.03`。
而 §5.13 记的「死路」用的是 SRS 口径的 `SE_chunk = 0.009772` ⇒ t = 1.667。
**两个 SE 差 18%，判决就跨过了 2.0 这条线。**
⇒ 「e4x 是死路」这个判决**本身贴在线上**，它对 SE 口径的敏感度与 §5.13 的教训一模一样。
**不要**据此宣布翻案（分层口径给 0.00899 ⇒ t=1.81，又回到线下）；
正确的读法是：**e4x 单独一个集根本没有把这条线定下来的分辨率。**

## 3. 第三个方差源：会话（2026-09-19 晚，零 GPU）

**脚本**：`scripts/g1_e4c_session_decomp.py`（只用已落盘的 `per_chunk` 计数）。
**产物**：`results/annotator/g1_e4c_session_decomp.json`。

### 3.0 一句话

**§2.10 的 σ̂ 反解看不见会话 —— 轮转抽样每一轮都含全部 100 个会话，会话构成
在轮间恒定，所以会话那一项方差被结构性地抵消掉了。** 把会话簇放进 bootstrap 后：
`SE` 从 0.00557 涨到 **0.00894**，`t` 从 4.61 掉到 **2.87**，地板从 0.00376 涨到
**≈0.0063**，`t` 上限从 6.8 掉到 **≈4.0**。**这是同一个病在本项目的第三次发作**
（[[permutation-test-covers-one-variance-source]]：固定住一个因子 ⇒ 它永远不进零分布）。

### 3.1 为什么轮转抽样看不见会话

`g1_e4c` 的抽法是**轮转**：每轮从 200 个 `(session, channel)` key 里各取 1 块。
于是**每一轮都包含全部 100 个会话**，且每个会话每轮恰好出 1 块。

⇒ 换一轮**不换会话**。若存在「某些会话上效应大、某些会话上没有」的结构，
它在轮与轮之间是**常数**，在轮间方差里**被抵消**。
§2.10 的 lag-1 检验、σ̂ 三档一致性，测的全是**轮间**那一层，**都对**，
**但都不是「会话」这一层的证据**。

> 这与 §2.7 的种子那一项是同一个道理：7 个种子在 16 批里**是同 7 个**，
> 所以加批买不到种子精度。现在多一条：**100 个会话在 24 轮里也是同 100 个**，
> 所以**加轮也买不到会话精度**。

### 3.2 三条 bootstrap 的对比（B=600）

| 重抽什么 | SE | 含哪些源 |
|---|---|---|
| 只重抽**种子** | 0.00368 | 种子 |
| 只重抽**会话**（簇） | 0.00527 | 会话 |
| 两向都重抽 | 0.00688 | 种子 + 会话 + 交互 |
| **三阶段**（会话 → 会话内块 → 种子） | **0.00894** | 上面 + **会话内块噪声** |
| §2.10 解析式（轮间 + 种子） | 0.00557 | ❌ **不含会话** |

⚠️ 第三行（0.00688）**仍不是总数** —— 它把 4800 块**当作固定的**。
「三阶段」那一行才是与 §2.10 同口径（块是抽来的）的总 SE：**0.00894**。
`hypot(0.00368, 0.00527) = 0.00643 < 0.00688` ⇒ 两个源之间**有正交互**，
不能简单相加。

**⇒ 头条数字改写：`ΔF1 = +0.0256`，`SE = 0.00894`，`t = 2.87`（不是 4.61）。**

判据「均值 > 2×SE」：`0.0256 > 0.01788` ✅ **仍然满足**，但余量从 2.3× 掉到 **1.43×**。
（§3.3 表里那一列是 **bootstrap 重抽的均值**（0.0255），与点估计 0.0256 差在第四位，属正常。）

### 3.3 地板与上限 —— §2.10 的结论被推翻

把「每会话块数」N 取 12 / 24 / 48，各做一次三阶段 bootstrap：

| 每会话块数 | 总块数 | SE | ΔF1 |
|---|---|---|---|
| 12 | 1,200 | 0.01395 | +0.0267 |
| 24 | 2,400 | 0.01068 | +0.0256 |
| 48（现有） | 4,800 | 0.00894 | +0.0255 |

拟合 `SE² = A/N + F` ⇒ `A = 1.851e-3`，`F = 3.962e-5`
⇒ **地板 `√F = 0.00629`（§2.10 说 0.00376，偏小 0.60×）**
⇒ **`t` 上限 `= 0.0256/0.00629 = 4.07`（§2.10 说 6.8）**

⚠️ 3 点拟 2 参只剩 1 df，**不能信单次拟合**。两两配对：

| 只用 | 地板 | t 上限 |
|---|---|---|
| N=12,24 | 0.00579 | 4.43 |
| N=12,48 | 0.00645 | 3.97 |
| N=24,48 | 0.00676 | 3.79 |

**三对全落在 0.0058–0.0068 / 3.8–4.4 ⇒ 结论对取点不敏感。**

🔴 **`N* = A/F = 46.7 块/会话`，而现在是 48 ⇒ 已经越过交叉点。**
**从这 100 个会话里再加块，买到的 SE 改善已经可以忽略。**

### 3.4 效应不是被少数会话撑起来的 ✅

- **逐会话 jackknife**（去掉一个会话，在剩下的并集上重算）：LOO ΔF1 落在
  `[+0.0235, +0.0268]`，**100 次里没有一次翻号**；SD 仅 0.00055。
- 单会话最大影响 0.0021 ≈ **0.31 × SE**（不是 1 个 SE 的量级）。
- 换句话说：**这个效应是弥散的，不是 3–5 个会话贡献的。**

这是本节唯一让人放心的结果，也是它值得记下来的原因：
**会话方差是真的（进 SE），但会话异质性不构成对结论的威胁（不进偏差）。**

### 3.5 顺带逮住一个**假机制**（差点写进结论）

逐会话计数给出：`ΔTP = +22`、`ΔFP = −85`（own10 相对 mixnorm **多命中、少误报**）。
pooled 看上去像一个干净的行为机制 —— **它是假的**。逐种子列出来：

| seed | 42 | 1234 | 7 | 2024 | 3407 | 31337 | 55555 | 均值 |
|---|---|---|---|---|---|---|---|---|
| ΔTP | +40 | −7 | +52 | +26 | +25 | −13 | +32 | +22.1 |
| ΔFP | **+648** | **−561** | +121 | +84 | −141 | **−1106** | +358 | −85.3 |

- `ΔFP` 跨种子 **SD = 588**，而臂间差只有 −85 ⇒ **臂间差 / 跨种子SD = 0.14**。
- 同一臂自己的摆幅：`FP_mix` 跨种子 SD = **629**（981 → 2687，**2.7 倍**），
  `FP_own` 跨种子 SD = 190 ⇒ **臂间差比同臂的种子噪声还小一个量级**。
- `ΔTP` 也没立住：比值 0.93（< 1）。

⇒ **「own10 少报 85 个假阳性」不是发现，是单次 run 摆幅下的一个数。**
这正是 [[permutation-test-covers-one-variance-source]] 里同一天栽过两次的坑：
**计数类量没有 F1 那种配对比值的自平均。**

**但留一条线索**（未确立，别当结论）：`FP_mix` 跨种子 SD 是 `FP_own` 的 **3.3×**
（629 vs 190）—— 这是**离散度**差、不是均值差，方向上与项目已有的
「mixnorm run 间阈值离散 2.88×」**独立吻合**。n=7 的 F 检验名义上过线
（F=10.9, df 6,6），但这是事后从一堆量里挑的 ⇒ **只作为线索登记**。

### 3.6 对本节自身的诚实清单

1. **100 个会话仍然是固定的**：3.2 的会话 SE 是「从这 100 个里重抽」，
   不是「从 CANDOR 里重抽」。要推广到**别的会话**，必须真有别的会话（见 §4）。
2. **每个会话恰好 48 块**（中位数=范围=48），所以「N 每会话块数」这个标度
   在现有数据上是**均匀**的；若将来各会话块数不等，`A/N` 那一项要换成加权形式。
3. **`F` 是从三档 N 外推的截距**，不是一个直接测到的量。它的可信度由
   §3.3 的两两配对撑住（3.8–4.4），不是由那个 1 df 的拟合撑住。
4. **`t = 2.87` 与 §2.10 的 `4.61` 都「对」**，只是**估计量不同**：
   前者把 4800 块当**样本**（要推广到别的块），后者把块当**总体**。
   本项目要的是前者。**报告时必须写明是哪一个**，否则就是 §5.13 那个病。

`t` 从 2.87 到 3.73 并不改变任何判决（判据「均值 > 2×SE」**现在就已经满足**：0.0256 > 0.0179）。

**C 真正买的是 §2.9 一直挂着的那条**：*「这个结论能不能推广到我没看过的会话？」*
现在 100 个会话是**固定的**，所有 SE 都是「从这 100 个里重抽」。
跑 100 个**全新**会话、用**同一批已训好的 adapter**（0 训练）、按**预登记**
判据检验 `ΔF1 > 0`，才是把「在这 100 个上成立」升级成「在 CANDOR 上成立」。

📌 **两种结果都要先写清楚**（沿用 §5.13 的规矩）：
- 复现（新会话上 `ΔF1 > 0` 且落在现区间附近）⇒ 结论升级，可以对外说。
- 不复现（`ΔF1 ≈ 0` 或翻号）⇒ **说明「效应」是这 100 个会话的性质**，
  那么 §2–§3 的所有 SE 讨论都只是在描述一个**不许外推**的点估计。

   就是在换一个**不同的问题**。按 §5.8 的教训，**开跑前先报正例率**。

### 4.6 另一条正交的路（更便宜，但没验证过）

**换端点：从 F1 换成连续量。** 4800 块只有 189 个真值事件 ⇒ F1 是个很钝的仪器；

唯一没试过的是**连续的 margin/score**（`ari_g1_margin_probe.py` 已有）——

- 它的**方差可以直接分解**，没有 F1 那个比值的麻烦（不用管并集/不可分解）；
- 若它的信噪比比 F1 高一个量级，**上面整张选型表都可以不算**。

⚠️ 但按 [[threshold-must-match-null-model]] 第六面：**引用现成 margin 产物前先核粒度/覆盖面** ——
已存在的 E2-400 margin 与 e4x **交集为 0**，不能直接拿来用。要跑就得**在新池上重跑探针**。

**建议**：把它当**并行的探针**，不要当 C 的替代 —— C 回答的是「泛化」，margin 回答的是「仪器」，
两个问题。

1. **§4.5 三个检查**（0 GPU，~1 h）—— 尤其第 1 条可能省 27 GPU·h。
2. **C：`--start 100 --n-sessions 100` + 建池 + 评估**（~56 GPU·h，两卡约 1.2 天），

5. **D（加种子）留给 C 之后**：会话没加上去之前，加种子的收益被会话项压住

### 5.1 检查 1：帧轨迹**能省**，省的是 C 的一半开销 —— 但不是零代价

先把机理说清（读源码，不是猜）：`ari_g1_eval4_ids.py` 里块网格是

```python
tmax = float(t0a[-1])          # 轨迹**最后一帧**的时刻
while t + CHUNK_S <= tmax:     # t = 0, 5, 10, …；CHUNK_S=10, STRIDE=5
    cid = f"{s8}_ch{ch}_t{int(t)}"
```

⇒ **网格完全由 `tmax` 这一个标量决定**（id 就是 t 的前缀）。
`tmax` 之外，轨迹还供一个 `fm.sum() < MIN_FRAMES` 的稀疏闸门。

在**全部 100 个已有会话 × 2 声道 = 200 对**上比两种口径：

| 事实 | 实测 |
|---|---|
| `tmax(轨迹) − 时长(mp3)` | **均值 +0.740 s**，SD 0.183（p1–p99 = [+0.70, +0.80]） |
| 两者差 ≤ 0.1 s 的比例 | **0%** —— 不是等价的 |
| **块数完全相同** | **168/200 = 84%**；其余 32 对**正好差 ±1 块**（都是末块） |
| `MIN_FRAMES=20` 闸门拦了多少 | **0 / 84,944 个网格位置** ⇒ **这个闸门是死代码** |
| 轨迹网格末块**越过** mp3 末尾的 | **30/200 = 15%**，越界最多 0.75 s |
| 帧率 | 12.5005 fps（恒定）；两声道**共用同一条时间轴** |

再加上一条早就知道、这次坐实的：`make_eval_wavs()` 从 npz 里**只读 `d["audio"]`**
（`ari_g1_common.py:50-51`），`predict_times()` 只吃 wav
⇒ npz 里的 `states`/`fused`（轨迹的另一个产物）**在评估路径上是死的**。

**⇒ 结论：C 的 100 个新会话不需要跑帧轨迹。**
按 §4.2 的成本模型，C 的 ~56 GPU·h 里 **27.25 h 是轨迹**（100 × 981 s）、
28.2 h 是评估（4800 块 × 14 adapter × 1.51 s）⇒ **省掉轨迹，C 从 ~56 掉到 ~29 GPU·h。**

⚠️ **这不是零代价的替换，要说清楚**：
1. 用 mp3 时长当 `tmax`，会有 **16% 的 key 少一个末块**（或多一个）。
   ⇒ **新池的块 id 与「用轨迹会得到的」不完全一样**，要记成**构造口径的一处变化**，
   不能写成「同一构造」。
2. 好在：C 是**全新会话上的全新评估集**，不需要和任何现有集逐块对齐；
   而且两臂用的是**同一个集**，比较不受影响。
3. 反而**更干净**：轨迹网格里那 15% 越过音频末尾的末块（尾部静音）消失了。

**⇒ 建议：给 `ari_g1_eval4_ids.py` 加一个 `--grid-from mp3` 开关**（小改动），
并在预登记里写明「网格口径由轨迹改为 mp3 时长」。

### 5.3 检查 3：🔴 **新池的流行率是 e4c 的两倍** —— 这条改变 C 的预登记

这一条比预想的严重，分两层。

**第一层：会话本身没问题。** 把 100 个已用会话和 100 个新会话的**原始网格**
（所有 `t=0,5,10,…` 位置）各扫一遍，用会话簇 bootstrap：

| | 事件/块 | 会话簇 SE |
|---|---|---|
| 已用 100 | 7.8301% | ± 0.3815% |
| 新取 100 | 7.9816% | ± 0.3876% |
| 差 | **+0.15%** | ± 0.54% ⇒ **t = +0.28，与 0 无异** |

⇒ **新会话与已用会话是同一档事件密度**，换会话没有换问题。

**第二层：但「候选池」的密度差一倍。** 这才是 C 实际会抽样的东西：

| | 候选块数 | 事件 | **候选池密度** |
|---|---|---|---|
| **e4c** 候选池（已用 100 会话，排除 3 个池） | 71,810 | 2,819 | **3.9257%** |
| （参考）**e4** 候选池（同会话，只排除 2 个池） | 76,425 | 3,000 | 3.9254% |
| **新池**（新 100 会话，无可排除） | 83,834 | 6,682 | **7.9705%** |

**比值 = 7.9705 / 3.9257 = 2.03×。**

> ⚠️ **2026-09-22 更正**：本表初稿把 `76,425 / 3,000` 标成「e4c 候选池」——**标签错了**。
> 那四个数是 **`g1_eval4_meta.json`（e4，1200 块那一版）** 的，
> 它的排除集只有 `g1_ids`+`g1_eval2`。e4c 的 meta（`g1_eval4c_meta.json`）记的是
> **71,810 / 2,819**，因为它还多排除了 `g1_eval4x_ids.txt`（1,600 块）。
> 两者密度几乎相同（3.9254% vs 3.9257%）⇒ **2.03× 这个结论不变**，
> 但凡引用「76,425」的地方要认准它是 **e4** 的池子。

**差从哪来 —— 是「被吃过」，不是「会话不同」：**
e4c 建候选时要排除**已用池**（`g1_ids.txt` 训练集 + `g1_eval2_ids.txt`=E2）
以及**与之时间重叠**的块。那两个池子自己的密度是：

| 被排除的池 | 块数 | 事件 | 密度 |
|---|---|---|---|
| `g1_ids.txt`（训练集） | 2,400 | 1,677 | **69.88%** |
| `g1_eval2_ids.txt`（E2） | 1,600 | 1,640 | **102.50%** |

它们几乎**全是「有事件」的块**（E2 按构造就是 100% 正例）。把稠密块挖走之后，
剩下的候选池自然稀：**7.83% → 3.93%**。
新会话**没被吃过** ⇒ 从新池自然抽样会得到 **~8%** 的集。

**锚点自检（会失败的那种）**：用轨迹网格 + 完整排除逻辑重跑已用 100 会话，得
**76,425 候选 / 3,000 事件 / id 丢弃 4,000 / 时间重叠丢弃 4,519** ——
与 `g1_eval4_meta.json` 记的**四个数全部逐位一致** ⇒ 排除逻辑是忠实的。
另：用 mp3 网格重算 `g1_eval4c_ids.txt` 的事件数得 **189 / 3.9375%**，
与文档记的 4800 块 / 189 事件**差 0**。

🔴 **为什么这条要紧**：流行率正是 §3.3 那次翻车的那个变量
（E2 的 100% 正例集把「mixnorm 不稳」这个伪影造了出来）。
**C 如果按原样跑，就是在一个两倍稠的集上做「复现」** —— 那不是复现，是换了个仪器。
而且按项目自己的历史，ΔF1 随流行率上升而变大（E2 100% → +0.124；
e4c 3.9% → +0.0256）⇒ **新池上的 ΔF1 大概率会更大**，
若不先写明白，会被误读成「效应在新会话上更强」。

**⇒ 对 §4.4 预登记的修改（两个读数，都要先写死）：**
- **主判据仍是符号**：新池上 `ΔF1 > 0`。流行率变了，**幅度不可直接比**。
- **附加一个「同仪器」读数**：因为逐块逐臂的计数都落盘了，
  可以在**事后**把新集**子采样/重加权到 e4c 的 3.93%** 再算一次 ΔF1
  （在并集上重算，**不需要额外 GPU**）。这才是能和 +0.0256 直接比的那个数。
- **预期要写死**：自然池（7.97%）上的幅度**应当比 3.93% 那档更大**。
  若反而更小，那是个需要解释的异常，不是「复现失败」。

### 5.4 顺带更正：已用的 100 个会话是 `sorted[0:100]`，**不是** `[1:101]`

§4.1 表里写「已用 100（= 排序后 `[1:101]`）」—— **错的**。实测：

- `e4_raw/` 里的 100 个会话在 `sorted(os.listdir(CANDOR))` 里的下标是
  **0–99，且连续**；
- `sorted[1:101]` 里的 `113c581b-…` **不在** `e4_raw` 里，
  而 `e4_raw` 里的 `0020a0c5-…` **不在** `sorted[1:101]` 里。

### 6.7 🔴 一个必须先说的实现事故：`boot()` 的合并层级**换了估计量**

这是本次最该记下来的东西，因为**它差点让一个错误的注释继续替我们做决定**。

**发现**：同仪器读数要抽稀，抽稀按**块**丢 ⇒ 会话块数参差（min 39 / max 48）
⇒ `boot()` 的 `reshape(S, C, 3)` 抛断言
（`AssertionError: 块数 4572 不能被会话数 100 整除`）。
查这个断言时读到了 `boot()` 的实现，发现它的合并层级**和它自己的文档字符串不一致**：

- 文档写：「会话重抽 = 抽行、块重抽 = 抽列 …… **与逐块重抽等价**且快得多」。
- 实际做：列下标 `ci` 对**所有会话共用** ⇒ 会话 i 抽 m_i 次、列 j 抽 n_j 次时
  和 = `Σ m_i·n_j·a[i,j]`，是一个**行×列的乘积测度**，既不是池化 iid 抽块，
  也不是聚类重抽。**那个"等价"只在 `block` 单层（会话抽为恒等）时成立。**

**实测两者差多少**（`g1_c_boot_ragged_probe.py`，B=4000 ⇒ MC 1.1%）：

| 层级 | e4c `boot` | e4c `boot_clustered` | C `boot` | C `boot_clustered` |
|---|---|---|---|---|
| sess | 0.00538 | 0.00538（+0.0%） | 0.00665 | 0.00665（+0.0%） |
| block | 0.00516 | 0.00518（+0.4%） | 0.00659 | **0.00723（+9.7%）** |
| seed | 0.00391 | 0.00391（+0.0%） | 0.00549 | 0.00549（+0.0%） |
| **all** | 0.01052 | **0.00917（−12.9%）** | 0.01379 | **0.01192（−13.5%）** |

- `sess` / `seed` 两集都**完全一致**；`block` 在 e4c 上差 0.4%（MC 内）、
  在 C 上差 9.7%（**超出** MC）；**合并层级两集都差 ~13%**。
- **点估计不受影响**（e4c 0.02527→0.02535，C 0.04263→0.04298，都是同一样本值上的抖动）。
- **冒烟的枪**：被改掉的文档字符串里还留着「本脚本初版实测 0.0054 vs 三级 **~0.0092**」
  —— 0.0092 正是 `boot_clustered` 现在给出的值。**加速改写换了估计量，注释没跟着改**，
  于是一条描述着"已不存在的函数"的注释留在原地，而所有后续读数都从它下面流过。

产物：`g1_logs/c_boot_ragged_probe_e4c.log`、`g1_logs/c_boot_ragged_probe_c.log`
（🔁 2026-09-23 重跑留档 —— 本表原先同样**没有落盘日志**，重跑后四行**逐位复现**；
两日志末尾另印点估计对照：e4c `0.02527→0.02535`、C `0.04263→0.04298`，
都在 MC 1.1% 以内 ⇒ 印证"点估计不受影响"）。

**处置**（三条，都保守）：
1. `boot()` **行为原样冻结** —— e4c/C 的预登记读数就是它算的，不许动。
   只**改正它的文档字符串**并把上表钉进去。
2. 新增 `boot_clustered()`：真·三级（会话 × 会话内块 × 种子），**块数不等时唯一有定义**。
3. **C 的 ✅ 判据在两种估计量下都成立**：`boot` t=+3.09，`boot_clustered` t=+3.61
   ⇒ **无结论翻转**。而且 `boot` 给的是**较大**的 SE（更保守），
   所以"保守的那个都过了"这个说法成立。
4. **产物里记下用的是哪个估计量**：`report()` 与 `matched` 都新增 `boot_estimator`
   字段（值就是函数名）。这与 §四.20 那次事故的修法**是同一条纪律** ——
   「把会变的东西在每一层都变成**返回值**，而不是写死在代码或产物里」。
   那次是**种子数**变了而产物仍写 7 个；这次是**估计量**变了而没人看得见。
   同一个坑，换了个字段。

⚠️ 仍然要记的账：**同仪器读数用的是 `boot_clustered`，主读数用的是 `boot`**。
两者在合并层级差 13%，所以这两个数**严格说不同口径**。
之所以还是这么选：主读数的口径是预登记的、不能动；而同仪器读数**只有** `boot_clustered`
能用（`boot` 在参差集上直接抛异常）。对照读数 `--matched-truncate`
（截断成方形 + 沿用 `boot`）见 §6.8。

1. **同仪器读数是 secondary，不是泛化判据**（prereg §4.2 原文）。判据只有 §6.1 那一条。

3. **t = −2.19 只是刚过线**。余量/MC ≈ 8 说明不是抖动，但也不宽裕。

4. **抽稀后的 C 仍然显著**（+0.0237 / draw 0 的 t=+2.95）⇒ 正确的说法是
   **"幅度主要由流行率决定"**，**不是**"新池没用"。
5. **"C 抽稀后 ≈ e4c"没有做正式检验**。两个不同构造、不同会话的集合，

6. **抽稀间 SD（0.0042）小于配对 SE（0.0085）**，说明抽稀这一步的随机

7. **并集读数（§6.6）与主读数一样用的是 `boot()`**，未重算 `boot_clustered` 版本。
8. `--skip-matched` 重跑复现了主读数的每一个数字（脚本确定性）⇒
