## 1. Q4：让 loss 曲线变得可读

### 1.1 背景（§4.3）

全项目 23 个训练 run 的 `trainer_log.jsonl` 里**每一行 loss 都是 0.0**，
而同行的 grad_norm 是 0.27–4.04。因果链已在真实训练数据上验证：
响应是纯文本 → `speech_labels` 整片 mask → `ForCausalLMLoss` 全 ignore 时
除零得 NaN（**但梯度是 0，不是 NaN**）→ 总 loss = NaN →
`logging_nan_inf_filter` 把它吞掉记成 0.0。

**训练没坏，记录坏了。**

### 1.2 修复中发现的一个真 bug

`scripts/g1_text_only_train.py` 的 `DisableSpeechCallback` 原本是
**鸭子类型对象**（不继承任何基类），注释里写着「LLaMA-Factory 只按名字回调
on_train_begin」。**这个假设是错的**，第一次跑就炸：

```
File ".../transformers/trainer_callback.py", line 556, in call_event
    result = getattr(callback, event)(
AttributeError: 'DisableSpeechCallback' object has no attribute 'on_init_end'
```

`transformers 4.52.3` 的 `call_event` 是**无默认值**的 `getattr(callback, event)`，
所以回调对象必须对**每一个**事件都有属性。修法是继承 `TrainerCallback`
（其余事件都有 no-op 默认实现），只覆写 `on_train_begin` / `on_log`。

⇒ **教训**：变换器框架里的「回调」是鸭子类型这个说法，只在
「它会按名字取属性、且取不到时有兜底」时成立。这里没有兜底。

### 1.3 中性校验的设计

关掉 speech 支路**应该**不改变任何一步更新（该支路梯度恒为 0）。
验证方式：用 `seed=42` + 默认 `data_seed` **重跑原配置**，
与既有 `g1_{arm}_sft` 比。

**判定口径刻意不设成「md5 相同」**：少跑一次 `audio_invert_tower` 前向
可能改变 dropout 消耗的 RNG 流，轨迹会漂移。所以口径是
**「落在跨种子噪声内」**（§7.4：SD ≈ 0.031），而不是逐位相同。

## 2. Q3：把「初始化运气」和「shuffle 运气」分开

### 2.1 要回答什么

§5 只测出「mixnorm 的种子会落在不同阈值上」，没解释来源。§7.1 用读盘证据
排除了 (a) 数据顺序、(b) LoRA 初值是**两臂差异**的来源，但那做不到
「(a)(b) 各自贡献多少」。本实验是它们的**直接干预版**。

### 2.2 设计

**固定 `seed=42`，只变 `data_seed`**，两臂各 7 个值
（`42 1234 7 2024 3407 31337 55555`，与既有种子研究同一组数）。

- `seed` 决定 LoRA 初值（以及 dropout 等一切 torch RNG）
- `data_seed` 单独决定**训练集的打乱顺序**
- 固定 seed ⇒ 7 个 run 的初值**逐位相同**，差异只能来自数据顺序
- 于是 `Var(data_seed | seed=42)` = **纯 shuffle 分量**
- 与既有跨 7 个 seed 的方差联立：
  `Var(seed) = Var(init) + Var(shuffle)`

**本段刻意不加 `DisableSpeechCallback`**，保持与原始 14 个 run 逐字相同的配置，
让 `data_seed` 成为唯一变量。附带好处：`ds=42` 那个 run 必须**复现**
既有的 `g1_{arm}_sft`（seed=42，data_seed 未设 ≡ 42），这是一次强校验 ——
它同时证明管线接对了、且配置确实只差这一个字段。

### 2.3 关键前提：`data_seed` 到底有没有生效？

这是本实验的**单点故障**：如果 `data_seed` 是空操作，14 个 run 会跑出
一模一样的 14 个 adapter，3 小时全废。所以先静态验证了一遍。

**先验发现**：`grep -rn "data_seed"` 在 **LLaMA-Factory 全仓库命中 0 次** ——
一度怀疑它是空操作。但管线其实走的是 transformers → accelerate，
不经过 LLaMA-Factory 自己的代码。逐环查证：

| # | 环节 | 结论 |
|---|---|---|
| 1 | `finetuning_args.disable_shuffling` | 默认 **False**（否则会走 `SequentialSampler`） |
| 2 | HF `trainer.py:1001 _get_train_sampler` | 无 group_by_length 时返回 **`RandomSampler`** ✓ 类型对得上 |
| 3 | `trainer.py:5137` | 从 `AcceleratorConfig` 取 `use_seedable_sampler`，**默认 True** |
| 4 | `trainer.py:5142` | `dataloader_config.data_seed = self.args.data_seed`（需 accelerate ≥1.1.0，实测 1.11.0） |
| 5 | `accelerate/data_loader.py:1176` | `isinstance(sampler, RandomSampler) and use_seedable_sampler` → 包成 `SeedableRandomSampler(data_seed=...)` |
| 6 | 同上 `__iter__` | `generator.manual_seed(self.epoch + self.initial_seed)`，而 `initial_seed` **就是 data_seed** |

⇒ **换 `data_seed` 必换顺序，实验有效。**

> ⚠️ 第 3 环有个**容易踩的坑**：accelerate **自己**的
> `prepare_data_loader(use_seedable_sampler=...)` 默认是 **False**，
> 而 transformers 的 `AcceleratorConfig` 默认是 **True**。
> 这里生效的是后者。只看 accelerate 的签名会得出「data_seed 无效」的**反结论**。

### 2.4 ⚠️ 原先设计的「第二道保险」是**无效的**（2026-09-17 20:15 发现）

脚本末尾原本比对 7 个 adapter 的 md5，全同就报「data_seed 疑似空操作」。
**这个检查永远不会 fail，等于没有。**证据来自一个**自然实验**：

| | `g1_own10_sft` | `g1_own10_ds42_sft` |
|---|---|---|
| `seed` | 未设（HF 默认 42） | `42` |
| `data_seed` | 未设（None） | `42` |
| `output_dir` | 自己的 | 自己的 |
| 其余全部字段 | **逐字相同**（`diff` 只有这两处） | |
| adapter md5 | `82f9e718…` | **`d5ca5b1b…`** ← 不同 |

而 `data_seed=None` 在 `SeedableRandomSampler.__init__` 里等价于
`torch.random.initial_seed()`，即 `set_seed(42)` 之后的 **42** ——
所以这两行**是同一份有效配置**，数据顺序也逐位相同（下方已验证）。

差异只有一个来源：基座 config 没有 `full_determinism`（默认 **False**），
cuBLAS/cuDNN 的非确定性 kernel 让**每次重跑都产生不同的比特**。
⇒ 「7 个 md5 互不相同」在 `data_seed` **完全无效**时也照样成立。
**这是个恒真的断言，提供的是虚假保证。**

`scripts/g1_dataseed_order_check.py` —— 不猜产物，直接复刻

判据应该是**「这棵树的启动时刻，晚于最后一次代码修改吗」**。

### 3.3 补跑怎么接上去：一条自驱动的链

Q4 不能现在起 —— gpu01 那张卡被 Q3 占着（21.9/23.5 GB），
此刻起第二个进程就是重演 §3.1 的抢卡 OOM。所以写成
`scripts/g1_q4_then_eval.sh`，**在同一个 srun 步骤里先等后跑**：

```
阶段 0  等: nvidia-smi 无进程 且 14 个 Q3 adapter 齐  ->  才往下走
阶段 1  G1_ONLY=q4 bash g1_q3q4_train.sh          (2 run, ~27 min)
        + 立刻打印 trainer_log.jsonl 的 loss 行统计  (§1.1 的核心问题)
阶段 2  bash g1_q3_eval.sh both                    (16 adapter, ~2.2h)
```

三个设计点：

1. **等待判据用「GPU 实际占用 + 产物齐」而不是「进程在不在」。**
   只看进程会把「崩了」也当成「跑完了」；而只等 GPU 空、
   不看 adapter 数，则可能在训练崩掉后带着残缺的 Q3 往下走。
2. **判据在 gpu01 上执行。** `nvidia-smi` 在 login01 上会**静默失败**并
   返回 0 个进程 —— 那会被误读成「GPU 空了」，然后一头撞进 OOM。
   所以脚本开头有一道 `nvidia-smi -L || exit 1` 守卫（已实测：
   在 login01 上正确拦下，在 srun 步骤内正确通过）。
3. **§3.2 的教训编进了脚本**：跑 Q4 之前把
   `g1_text_only_train.py` 的 mtime 和本阶段的启动时刻**都打出来**，
   让「读的是修复后的版本」这件事可见，而不是靠记性。

> 等待期间该 srun 步骤只跑 `sleep`，不占显存；**所有实际计算都在
> srun 步骤内**，login01 上不跑任何东西。

## 4. 结果

### 4.00 先说清楚：这个拆解**精度很差**（结果落地前就记下来）

`scripts/g1_q3_analyze.py --group seed` 的自检通过了（SD = 0.0309、ΔF1 = +0.0340，
复现 §7.2），但它顺带暴露了一个必须在**看到 B 组结果之前**就写下来的事实：

```
A 组 SD = 0.0309   95% CI [0.0199, 0.0681]
```

**7 个点估出来的 SD，其 95% 置信区间跨了 3.4 倍。** 于是：

- `Var(init) = Var(A) − Var(B)` 是两个**各自都很糊**的量相减 ——
  区间会宽到几乎无法支持任何定量断言。
- 如果这个差值为**负**（完全可能），正确的做法是如实报「两项在现有精度下
  分不开」，**不是裁剪成一个小正数**再讲「初值只占 3%」的故事。
- 本项目已经栽过一次「用 2–3 个点估 SD，把噪声包装成 7.6 SD 的异常」
  （见 memory `sd-from-few-points-manufactures-anomalies`），
  这次是 7 个点，好一些，但没到能定量拆分的程度。

### 4.4 ✅ 意外收获：Q3 的拆解框架**有证据支撑**（2026-09-18 00:2x）

`scripts/g1_same_config_replicates.py`（纯读盘，0 GPU）。

**Q3 的全部立论是「把 Var(seed) 拆成 Var(init) + Var(shuffle)」。**
但如果**同配置重跑一次**的离散就和跨种子 SD 同量级，那拆出来的两块
就是**噪声的分解**，没有物理含义 —— 拆解不可解读。
所以这一步是 Q3 能否成立的前提，必须先量。

**哪几份产物算「同配置」**（读**落盘**的 `training_args.bin` 核对，
不靠推断 —— 见 memory `config-differs-from-config-file`）：

| 标签 | 走的代码路径 | `seed` | `data_seed` |
|---|---|---|---|
| A 原始 `g1_own10_sft` | `train_plain` | 42 | **None** |
| B 组 `g1_own10_ds42_sft` | `train_plain` | 42 | **42** |
| Q4 `g1_own10_q4_sft` | **`train_textonly`** | 42 | None |

逐字段比对：A 与 B 组**只差 `data_seed`（None↔42）**，其余字段
（batch 4 / accum 8 / lr 2e-4 / epochs 2 / save_steps 25 /
`full_determinism=False`）**逐字相同**。而 §2.3 已逐环验证
`data_seed=None ≡ 42` ⇒ **A 与 B 组是同一份有效配置，构成一对纯重复**。

**Q4 不算纯重复**：它走 `train_textonly`，`DisableSpeechCallback`
少跑一次 `audio_invert_tower` 前向，**改变了 dropout 消耗的 RNG 流**
（§1.3 早已写明）。它量的是另一个量。

**结果**：

| 组 | ΔF1 | 说明 |
|---|---|---|
| ① 纯重复 A | +0.0440 | 同代码同配置 |
| ① 纯重复 B 组 ds42 | +0.0480 | 同上 |
| | **之差 = 0.0040** | = 跨种子 SD 0.0309 的 **13%** |
| ② RNG 流扰动 Q4 | +0.0707 | 与 A 差 +0.0267，与 B 差 +0.0227 |

**判读**：

- ✅ **纯重复之差 0.0040，仅为跨种子 SD 的 13%** ⇒ `seed=42`
  把运行**钉得相当死**；跨种子的 0.0309 是**真实的种子间差异**，
  不是运行噪声。⇒ **Q3 的方差拆解框架成立，拆出的两块有物理含义。**
- ✅ **Q4 的 +0.0267 可完全归因于 RNG 流扰动** ⇒ 这**反过来印证了
  §1.3 的预判**（"少跑一次前向会改变 RNG 流、轨迹会漂移"），
  也说明 §1.3 选的那把尺子（**落在跨种子噪声内**）从一开始就是对的。
  §1.5 我一度改成"应远小于跨种子 SD"是**把模型搞错了**。
- ⚡ **一个附带的物理洞见**：训练对 **RNG 消耗顺序**的敏感度（~0.027），
  比它对**浮点非确定性**的敏感度（~0.004）**大 6 倍**。
  换掉哪几个随机数被抽走，比 CPU/GPU 上少几位有效数字重要得多。

> ⚠️ **纯重复只有 n=2** —— 极不可靠，只报量级、不报 CI。
> 但它是**下界**性质的证据：运行噪声不会小于 0.0040。
> 要收紧，得跑更多次重跑，或开 `full_determinism` 后再比。
> （`full_determinism=False` 见配置表最后一行。）

> 🔴 **本脚本第一版把 ① 和 ② 混为一谈，结论会反向。** 它把 Q4 也当纯重复，
> 算出"同配置极差 0.0267 = 跨种子 SD 的 86%"，判读写成
> 「种子间差异可能主要是运行噪声，Q3 拆解框架要重新审视」—— **那是错的**，
> 而且恰好把整篇的主旨往反方向带。
> 错在**把「混沌敏感度」记成了「复现性差」**：两个量物理上不同，

#### 4.5.2 拆解 —— 以及**为什么不能报那个百分比**

    Var(init) = Var(A) − Var(B) = 0.000956 − 0.000910 = 0.000046   ← 占 4.8%

🔴 **这个 4.8% 不能报。** 它是两个噪声量相减得到的裸点估计，配误差棒：

| 量 | 值 |
|---|---|
| F = Var(A)/Var(B) | **1.051** (df=6,6)，双侧 **p = 0.95** |
| Var(A) 95% CI | [0.000397, 0.004637] |
| Var(B) 95% CI | [0.000378, 0.004412] |
| **Var(init) 保守区间** | **[−0.004015, +0.004259]** ← **横跨 0** |

F 几乎正好是 1，p=0.95 —— **完全无法拒绝 Var(A)=Var(B)**。
区间上界换算成 SD = **0.0653**，比总 SD 0.0309 **还大** ⇒ 这个拆解对
`Var(init)` 的约束力**几乎为零**。

> ✅ **正确的说法**：**init 分量在 n=7 下检不出**；
> shuffle 占**已分辨部分**的几乎全部。
> ❌ **不要写**「shuffle 95.2% / init 4.8%」。
> （memory: `sd-from-few-points-manufactures-anomalies`）

（memory: `expand-eval-set-buys-diagnosis-not-power` —— 这是同一个模式的第四次出现。）

**Q3 真正回答了的是一个设计问题**：种子间那 0.0309 的抖动，
**不是「初始化运气」造成的**，而是**数据顺序**造成的 ——
所以换种子重训并不会因为「换了个初值」而探索到不同的东西，
它探索的是**不同的数据顺序**。这解释了为什么 §7.2 的 7 个种子离散那么大：
7 个 seed 同时意味着 7 个 data_seed，**两个随机源被绑在一起动了**。

> 这也**反过来解释了 k=4 那件事**：如果抖动由数据顺序主导，
> 那么「评估集换一批块」和「训练数据换一个顺序」是**同族**的扰动 ——
> 换评估集能改判结论（§5），换训练顺序同样能。两者都不是噪声，是**信号的一部分**。
