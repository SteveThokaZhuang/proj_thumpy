# F8c：事件式任务——打通"训练→行为"的关键一步

> **日期**：2026-08-28
> **动机**：[F7](2026-08-28_f7_behavior.md) + [F7b](2026-08-28_f7b_framewise.md)
> 证明词序列任务在行为层面无效（任何粒度 ≈ 随机）。F8c 换任务形式：
> **直接输出 BC 事件时间戳**（"backchannel at 3.4s, 7.1s"）。
> **结果**：训练第一次传导到了行为层。
>
> **脚本**：`ari_f8c_build_event_data.py`（事件标签：X2-Turn p_bc 峰值事件 +
> AWS 窗口共识过滤）+ `f8c_sft_config.yaml`（LoRA SFT）+ `ari_f8c_evaluate.py`
> （±0.5s 命中 realized 真重叠窗口的行为级评估）

---

## 1. 设置

- 任务：输入 10s 对方声道音频；输出 = BC 事件时间列表或 "no backchannel"。
- 标签：X2-Turn p_bc ≥ 0.2 的连续帧段 → 峰值时间（与 AWS BC 窗口共识过滤，
  只保留标注器与 GT 都确认的事件）。
- 数据：2,400 块（1,800 含事件、600 负例）；LoRA rank 16、2 epochs、
  单卡 ~15 分钟。
- 评估：冻结 300 块；预测时间戳落在 realized 真重叠 BC 窗口 ±0.5s 内 = 命中。

## 2. 结果（300 块，26 个真重叠 BC 窗口）

| 模型 | 精度 | 召回 | F1 | 预测事件数 |
|---|---|---|---|---|
| 基座 | 0.025 | 0.192 | 0.044 | 201 |
| **F8c 事件式** | **0.074** | **0.385** | **0.124** | 135 |
| 词序列 12k（对照） | 0.015 | 0.154 | 0.028 | 265 |

## 3. 裁决

1. **"训练→行为"第一次打通**：事件式 LoRA 相对基座 F1 ×2.8（0.044→0.124）、
   召回 ×2（0.192→0.385）；相对最好的词序列模型 F1 ×4.4。
   任务形式（事件定位 vs 逐块描述）是行为传导的决定因素——与 F7b 的
   "词序列任务行为极限"结论互证。
2. **精度仍低（0.074）**：模型 135 个预测对 26 个真窗口——过生成严重。
   但方向正确，且这是所有训练变体中唯一有行为信号的一个。
   提升路径明确：负例增强、事件数上限约束、软分数蒸馏（用标注器的
   帧级概率做回归目标而非硬事件）。
3. **对飞轮故事的意义**：Paper 3 的核心链"标注→训练→行为"已完整走通，
   虽然行为强度还弱（F1 0.12 vs 标注器软分数 AUC 0.65 的上限），但
   任务形式的正确解已找到，后续是工程放大问题而非方向问题。

## 4. 下一步

1. F8c v2：软分数回归目标（帧级概率曲线）+ 负例增强 + 事件数约束；
2. F7 完整版：事件式模型接入对话重放回路（+TTS），端到端 BCRR/BCA/TBR；
3. F9 事件式对照：合成 metadata 事件标注 vs 真实事件标注（预言应延续）。
