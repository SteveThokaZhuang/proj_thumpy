## 1. C 是什么，为什么要跑

§2–§3 的所有结论都建立在**固定的那 100 个会话**上（`sorted[0:100]`）。
所有 SE 都是「从这 100 个里重抽」——包括 §3 那张方差分解表。

**C 用 100 个全新会话、同一批已训好的 adapter（0 训练）**，
按下面的判据检验 `ΔF1 > 0`。这是把

> 「在这 100 个会话上成立」

升级成

> 「在 CANDOR 上成立」

的唯一一条还没走过的路。加块、加批都到头了（§3.3、§4.0）。

**C 的主要产出不是 t 变大**（§4.4）。t 从 2.4 到多少都不改变任何已有判决。

### 2.1 ⚠️ 一个必须写明的**构造变更**

e4c 的网格由**帧轨迹的最后一帧时刻** `tmax` 定，而 `tmax − mp3时长 = +0.740 s`（§5.1）。
C 改用 **mp3 时长**定网格。后果，如实记：

- **84% 的 (会话,声道) 网格逐块相同**；其余 **16% 少一个末端块**（±1）。
- 轨迹网格下 **15% 的末端块会越过 mp3 结尾**（音频短于 10 s）；mp3 网格不会。
  ⇒ 这一条上 **mp3 网格更干净**，但两个集**不是同一构造**。
- 稀疏闸门 `MIN_FRAMES=20` 在 84,944 个网格位置上**一次没拦过**（§5.1）⇒ 是死代码，
  mp3 口径下直接跳过，**这不构成风险**。
- 不写 `states`/`fused`：评估路径只读 npz 的 `audio`
  （`make_eval_wavs` → `predict_times`），已逐行核实。

**⇒ 结论里必须说「C 是 mp3 网格上的新会话集」，不许说成「和 e4c 同一构造换批会话」。**

## 3. 主判据（预登记，不可事后改）

### 3.1 基线（同一天用同一份产物现算，不是抄文档）

`scripts/g1_c_analyze.py --set e4c`，2026-09-22 实测：

| 量 | 值 |
|---|---|
| **e4c ΔF1** = F1(own10) − F1(mixnorm) | **+0.0256** |
| F1[own10] / F1[mixnorm] | 0.0820 ± 0.0065 / 0.0564 ± 0.0097（跨 7 种子） |
| 逐种子 ΔF1 | +0.0229, +0.0097, +0.0451, +0.0227, +0.0343, +0.0235, +0.0214 |
| **三级 bootstrap SE** | **0.0105**（会话 0.0054 \| 块 0.0052 \| 种子 0.0039） |
| **t** | **+2.40**，95% CI [+0.0050, +0.0465] |
| 流行率 | 189 事件 / 4800 块 = **3.9375%**（含事件块 181 = 3.7708%） |

> ⚠️ **t = +2.40 比文档里那个 2.87 低。** 2.87 来自 §3 的方差模型；
> 这里是三级 bootstrap 现算的，**三级缺一不可**（见 `g1_c_analyze.py` 里那条注释：
> 只抽会话 0.0054、只抽块 0.0052、只抽种子 0.0039，合并 0.0105 **大于三者的
> 平方和根 0.0085**——各级不独立，所以不能靠分量相加代替联合重抽）。
> 以后引用 e4c 的 t，用 **+2.40**。

### 3.2 判据

**主读数（primary）：新 100 会话 × 4800 块的 `ΔF1 > 0`，用三级 bootstrap 的 t 判。**

| 结果 | 判读 | 写进结论的说法 |
|---|---|---|
| `ΔF1 > 0` 且 `t ≥ 2` | ✅ **复现** | 「效应不依赖那 100 个会话，可对外说」 |
| `ΔF1 > 0` 且 `t < 2` | ⚠️ **方向一致，未达可判定** | 「新样本上方向一致但样本量不够」 |
| `ΔF1 ≤ 0` | 🔴 **不复现** | 「效应是那 100 个会话的性质；§2–§3 的所有 SE 只是**不许外推**的点估计」 |

⚠️ **判据是符号，不是「落在 +0.0256 附近」。** 理由见 §4。

**为什么要三级 bootstrap 而不是「和 2×SE 比」**：会话是「换一批」时的抽样单元，
只按块重抽会漏掉会话那一项（`permutation-test-covers-one-variance-source`）；
反过来只抽会话漏掉块（本次实测 0.0054 vs 0.0105）；只抽种子漏掉前两项。
**本项目在这三级上各翻过一次车**，所以三级全开。

### 3.3 什么时候 C 的结果**不可判读**（先写死，免得事后找补）

1. **产物不全**：新池 npz < 4800 或评估 < 14 个 adapter。判读脚本会因并集变小而失真。
2. **新旧会话有重叠**：`g1_c_meta.json` 里的 assert 会炸；若绕过，整个 C 失去意义。
3. **新池流行率超出 [6%, 10%]**：预期 7.97%（§5.3）。落在这个带外说明池子构造出了问题
   （比如排除逻辑误伤了新会话），此时**先查构造，别急着判读**。

   > **2026-09-23 补记（在 C 跑完之前写，是把判据收紧、不是放松）**：
   > 「新池流行率」在这套流程里其实是**两个不同的量**，原文没说清是哪一个：
   >
   > | 量 | 定义 | 值 |
   > |---|---|---|
   > | **候选池密度** | 全部可选块 83,834 里的 6,682 个事件 | **7.9705%** |
   > | **评估集实测率** | 实际抽中的 4,800 块里的 415 个事件 | **8.646%** |
   >
   > 本条**约束的是候选池那个（7.97%）** —— 它才是「池子构造有没有出问题」的量，
   > 因为排除逻辑作用在候选池上。评估集实测率是**下游抽样**的结果，两者不同不构成异常。
   > （老账 `prevalence-flips-variance-conclusions` 已记过这类混淆：
   > 报流行率必须注明是「原始网格」还是「排除历史用块」。）
   > 两个量目前**都在 [6%, 10%] 带内** ⇒ 本条判据 ✅。此补记写于读到任何 ΔF1 之前。

## 4. 🔴 最要紧的一条：**幅度不可直接比**

§5.3 实测：**新池的流行率是 e4c 的两倍**（7.9705% vs 3.9257%，比值 2.03×）。
原因是**被吃过**——e4c 建候选时排掉的三个池子（`g1_ids` 69.9%、E2 102.5%、
e4x）几乎全是事件块，把已用会话挖稀了；新会话没被吃过。

**流行率正是 §3.3 那次翻车的那个变量。** 所以：

### 4.1 预登记的预期（写死，事后不许改）

1. **方向**：新池上 `ΔF1 > 0`。
2. **量级**：按项目自己的历史，ΔF1 随流行率上升而变大
   （E2 100% → +0.124；e4c 3.9% → +0.0256）
   ⇒ **预期 `ΔF1(C) > +0.0256`**。
3. **若 `ΔF1(C)` 反而更小**：那是**需要解释的异常**，**不是**「复现失败」。
   可能原因：新会话的效应本来就弱（异质性），要按会话级去看分布，不能只看均值。

### 4.2 同仪器读数（secondary，纯读盘 0 GPU）

逐块逐臂的计数都已落盘（`per_chunk` 里有 `tp`/`fp`/`n_gt`/`pred_times`/`wins`）
⇒ 可以在**事后**把新集**子采样到 e4c 的流行率 3.9375%** 再算一次 ΔF1。

- 做法：含事件的块全留，不含事件的按概率 q 抽，
  `q = (gt/target − n_pos)/n_neg`（`g1_c_analyze.downsample_to`）。
- **只有这个数**能和 e4c 的 +0.0256 并排。
- 主读数（2.03× 稠）与同仪器读数**方向不一致**时，以**主读数**为泛化判据、
  以**同仪器读数**为机制解释，并**两个都报**。

### 4.3 不许做的事

- ❌ 不许说「新池上效应更大 ⇒ 效应更强」——流行率变了，仪器就变了。
- ❌ 不许把 C 的 ΔF1 和 e4c 的 ΔF1 直接做 t 检验（两组不同流行率、不同构造）。
- ❌ 不许只看均值。§3.4 那套「效应不是被少数会话撑起来的」检查
  （留一、会话级分布）**在 C 上要重做一遍**。

## 6. 事后追加

（只允许往下加，不允许改上面的内容。每条带时间戳。）

### 6.1（2026-09-22 19:50）🔴 §4.2 的「同仪器读数」**方法不可行**，改为「抽稀事件块」

**背景（写这条时仍是盲的）**：14 个 adapter 里当时只跑完 2 个（seed 42 的两臂）。
`load_set("c")` 与 `boot()` 被跑通以验证代码路径，但**返回的数值没有被打印、没有被看过**
——**没有任何 C 的 ΔF1 被算出来或看到**。方法的选择因此不是看着结果挑的。

**问题**：§4.2 写的是「含事件的块全留，不含事件的按概率 q 抽」，
`q = (gt/target − n_pos)/n_neg`。这个式子**只能把流行率往下稀释到
`gt/(n_pos+n_neg)` 为止** —— 那是「一块不抽」时的值，也是本法可达的**下界**。

实测：

| 量 | e4c | C |
|---|---|---|
| 块数 | 4800 | 4800 |
| 含事件块 `n_pos` | 181 | **399** |
| 无事件块 `n_neg` | 4619 | 4401 |
| 事件 `gt` | 189 | **415** |
| 当前流行率 | 3.9375% | **8.6458%** |
| 本法可达下界 | 3.9375% | **8.6458%** |

- **e4c**：target = 当前值 ⇒ `q = 1`，原样返回。这是自洽性检查，通过（§4.2 已说明）。
- **C**：target 3.9375% **低于**可达下界 8.6458% ⇒ 式子的 `q = 2.304`，
  被 `min(1.0, …)` **静默夹成 1**（实测输出：`4800 -> 4800 块, 实际 8.6458%`）。
  **即：这个读数在 C 上根本算不出来，而代码不报错、只是原样返回。**

> ⚠️ 这正是本项目那一族坑（`hardcoded-conclusions-escape-reproduction`、
> `threshold-must-match-null-model`）：**一个恒真的操作伪装成一次变换**。
> 教训：`downsample_to` 遇 `q > 1`（目标低于可达下界）必须**炸**，不许 clamp。

**根因**：流行率 = `gt/块数`。C 的候选池没被吃过（§4.2 / §5.3），所以事件**稠**；
要降到 e4c 的稀度，只能**丢掉一部分事件块**，不可能靠丢无事件块做到。

**改用的方法（写死在这里，等跑完照此执行）**：

对目标流行率 π = 3.9375%、随机种子 r：

1. **保留全部 `n_neg` 个无事件块。**
2. 从 `n_pos` 个含事件块中**无放回随机抽 p 个**，p 由二分搜索定，
   使保留集的流行率 `Σgt(保留) / (p + n_neg)` 最接近 π（容差 0.02 个百分点）。
3. 在保留集上算 ΔF1，**仍用三级 bootstrap**（会话 × 块 × 种子），与主读数同口径。
4. 对 **R = 200 个随机种子**各做一次，报：
   - **ΔF1 跨 200 次抽样的均值**（这是要跟 e4c 的 +0.0256 并排的那个数）
   - **跨 200 次的 SD**（抽稀本身带来的额外随机，必须单独报，不许并进 bootstrap SE）
   - bootstrap SE 的均值

**必须一起说明的三件事**：

- 事件数从 **415 掉到约 180**（留存 ~43%）⇒ 这个读数**天然比主读数吵**，
  **它只是机制检查，不是泛化判据**（§4.2 已定：以主读数为泛化判据、两者并报）。
- 抽稀是**随机的**，所以「哪一个数」本身有抽样误差 —— 这正是要跑 200 次的原因。
  引用时**不许只报单次抽样的结果**。
- 这不改变 §3.2 的主判据，也不改变 §4.1 的预登记预期。主读数照旧。

**同一批保留集对所有 14 个 (arm, seed) 组共用**（各组 cid 相同，遵循并集口径）。
