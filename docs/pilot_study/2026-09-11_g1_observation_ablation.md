## 1. 假设与动机

BC 定义上是一个**跨说话人事件**：对方还在说 + 我插一个短 token。但当前 F8/F8c
的训练输入是 **10s 单声道、只有本人声道**。对方只可能通过麦克风回声/串扰进入，
而 CANDOR 用的是独立近场麦。

于是有一个很自然的怀疑：**模型访问不到标签所依赖的那个变量**，这就是精度
0.08、F1 0.127 上不去的根本原因。若成立，把对方声道直接给模型应当是最大的
单点改进。

本消融就是把这句话变成一个可证伪的实验。

## 2. 设计

| | own 臂 | mixnorm 臂 |
|---|---|---|
| 音频 | 只有本人声道（= 现状管线） | 本人 + 对方，逐声道电平匹配后相加 |
| 训练块 | 2,100 | 2,100（**同一批 id**） |
| 标签 / instruction | 相同 | 相同 |
| 评估集 | 冻结 300 块 / 26 个真值窗口 | 同一批 |
| 超参 | LoRA、batch 4×accum 8、132 步 | 相同 |

**不变量**：除音频本身外一切相同。两臂各训到 132/132 步（own 12:25，mixnorm
11:54），adapter 均 265,962,288 B 正常落盘，grad_norm 均值 0.550 vs 0.522，无发散。

`mixnorm` 的三道保护（`ari_g1_prep.py:make_audio`）：p95 而非 RMS 估响度并按
+30dB 封顶（对方真静音时不放大底噪）；对方峰值不超过本人峰值；整体 RMS 对齐
本人后做 0.99 峰值保护（避免 PCM_16 削波，v1 的 RMS 版有 31% 的块峰值 >1）。

**own 臂音频与 f8 管线逐位一致**：300 个评估块 max|diff| = 3.052e-05 = 1/32768
（PCM_16 量化底噪）。两臂评估音频出自同一条代码路径。

**训练/评估不重叠**：2,100 训练块与 300 评估块交集为 0，覆盖 94 个 session。

## 3. 操纵检验 ①：本人声道里到底有没有对方？

在讲主结果之前必须先钉死前提。`ari_g1_leakage.py`（**session 级**，25 个 session
/ 1,474,262 帧 / 30 段×2 声道包络互相关）：

| 量 | 值 | 含义 |
|---|---|---|
| 帧类别占比：双方都在说 | 0.0002 | 几乎不存在 |
| 仅本人在说 | 0.0723 | |
| 仅对方在说 | 0.0723 | |
| 双方都静音 | **0.8553** | X2-Turn 标签的极端稀疏性 |
| 包络互相关 中位 | **−0.373** | 本人声道里找不到对方 |
| 互相关 p90 / p99 | 0.000 / 0.126 | |
| 互相关 > 0.5 的比例 | **0.13%** | |
| 对方说话帧能量 − 本人说话帧 | **−11.2 dB** | |
| 对方说话帧能量 − 静音帧 | **−7.1 dB** | **对方说话时比静音还低** |

**裁决**：本人声道里**确实没有对方**——对方说话时该声道的能量甚至比静音段更低
（近场麦的隔音 + 噪声门效应）。前提成立。

（附带发现：X2-Turn 标签给 85.5% 的帧打"双方静音"，仅 0.02% 打"双方都在说"。

## 4. 主结果：零

事件级评估（预测时刻落在真值 AWS BC 窗口 ±0.5s 内算命中，每个真值窗口最多被
匹配一次），300 块 / 26 个真值窗口：

| 臂 | 精度 | 召回 | F1 | 预测数 | tp | fp |
|---|---|---|---|---|---|---|
| own10 | 0.1062 | **0.4615** | **0.1727** | 113 | 12 | 101 |
| mixnorm | 0.0946 | 0.2692 | 0.1400 | 74 | 7 | 67 |

**ΔF1 (mixnorm − own10) = −0.0327**。

26 个真值事件、tp 12 vs 7 —— 这个量级下必须给区间，否则任何结论都站不住。
`ari_g1_bootstrap.py` 做**配对** bootstrap（同一组 chunk 下标同时作用于两臂，
消掉 chunk 难度带来的方差；10,000 次，seed 0）：

- **95% CI = [−0.118, +0.048]**，跨 0
- **P(ΔF1 > 0) = 0.215**

**裁决：两臂差异不显著，观测空间不是瓶颈。** 两轮评估逐位相同（贪心解码确定性），
可复现。

## 5. 操纵检验 ②：mixnorm 臂真的把对方送进去了吗？

零结果最容易被质疑的一点是"你根本没把对方送进去，所以这个零什么也说明不了"。
`ari_g1_mix_check.py` 对每个块做最小二乘分解 `mix = a·own + 残差`，检查残差是否
就是对方声道。

全 300 块（不是抽样）：

| 分层 | n | 对方占 mix 能量（中位） | p10 | p90 | corr(残差,对方) | 对方被压没 |
|---|---|---|---|---|---|---|
| 全部 | 300 | 18.7% | 0.0% | 46.1% | 1.0000（270 有效） | 62 (20.7%) |
| **含真值 BC 的块** | **25** | **39.2%** | **12.3%** | 46.5% | **1.0000（25/25）** | **1 (4.0%)** |
| 不含 BC 的块 | 275 | 14.7% | 0.0% | 45.8% | 1.0000（245 有效） | 61 (22.2%) |

（25 个块承载全部 26 个真值窗口。对方相对本人的能量中位 −0.3 dB；gain 中位 1.095，
60 个块顶到 +30dB 上限。）

**裁决：操纵有效。** 在**恰恰承载真值 BC 事件的那 25 个块**上，对方贡献了 mix 中位
**39.2%** 的能量，残差与真实对方声道相关系数 **1.0000（25/25 有效）**，只有 1 个块
被压没。**所以零结果不是"没送到"，而是"送到了也没用"。**

**关于那 20.7% 被压没的块**：集中在 `make_audio` 的增益规则
`gain = min(p95(own)/p95(part), 30)` —— 本人声道静音时 `p95(own)≈0`，对方被压成
静音。这是一个**设计好的保护**（避免在本人静音处把对方底噪放大），而不是 bug。
它与本次结论无关，因为：被压没的块在不含 BC 的块里占 22.2%、在**含 BC 的块里只占
4.0%（1/25）**——即失效恰好发生在"听话人本来就没出声"、因而不需要判断的地方。

## 6. prompt 混淆的隔离

**背景**：v2 **训练**用 "...with confidence..."，但当时的评估脚本漏了这一段 ——
已发表的 0.127 是在**不匹配** prompt 下测的。为确认这不是 G1 结论的混淆，
拿**产生 0.127 的那个 v2 adapter**，在同一批 300 块、同一份 own 音频上只换 prompt：

| v2 adapter 的 prompt | 精度 | 召回 | F1 | 预测数 |
|---|---|---|---|---|
| 旧（**不匹配**，= 当初发表 0.127 用的那个） | 0.0800 | 0.3077 | **0.1270** | 100 |
| 匹配训练（"...with confidence..."） | 0.0748 | 0.3077 | 0.1203 | 107 |

**① 旧 prompt 逐位复现了已发表的 0.1270**（P 0.08 / R 0.3077 / n_pred 100）——
这是对整条评估管线的端到端校验：复现不了就说明 harness 与当初不等价。**复现成功。**

**② 纯 prompt 效应 = −0.0067**，且方向与"改了 prompt 就能解释一切"相反（匹配
prompt 反而略低）。**prompt 混淆关闭**：它顶多值 0.007，远小于本节要解释的量级。

## 7. run-to-run 噪声：干净测量 **SD ≈ 0.031、极差 0.096 F1**

这是本次消融最重要的副产品，也是解读第 4 节那个"零"的标尺。
§7.1 是最初的**上界估计**（0.05）；§7.2 用 2 个种子把它修到 0.016–0.024；
§7.3 追查 §7.1 那 0.052 未果；**§7.4 再用 5 个种子把样本补到 7 个，才发现 §7.2
的低估了约一倍，而 §7.3 追的那个"谜"根本不存在。**

> **读法提示**：§7.2 和 §7.3 保留原样作为**过程记录**（它们的"数据"没错，错在
> 样本量不够时的判读），但**结论一律以 §7.4 为准**。§7.2 的 0.016–0.024 与
> §7.3 的"7.6 个标准差"都已被 §7.4 推翻。留着它们是因为这个翻车过程本身

### 7.3 那 0.052 到底哪来的？—— 排查后**仍未找到原因**（2026-09-13）

§7.2 初稿曾把 0.052 归给 **micro-batch 切分（8×4 vs 4×8）**。**该推断是错的**，
2026-09-13 直接查产物后推翻：

**① micro-batch 根本没有差异。** 读 `f8c_v2_sft/saves/training_args.bin`（落盘的实际
生效值，不是配置文件）：

| run | micro × accum | 实际用的 config |
|---|---|---|
| f8c_sft (v1) | **8 × 4** | `f8c_sft_config.yaml` |
| **f8c_v2** | **4 × 8** | `f8c_v2_config_small.yaml` |
| g1_own10 / mixnorm / 各种子臂 | **4 × 8** | 由 `f8c_v2_config.yaml` sed 而来 |

v2 与 own10 的 micro-batch **完全相同**。缘由：v2 最初按 `f8c_v2_config.yaml`（8×4）
起跑，崩了之后 27 分钟时改出 `_small`（4×8）才成功 —— 我在文档里只看了 base 配置，
没看 `_small`，于是把 v1 的配置当成了 v2 的。

**② cutoff_len 是空操作。** `_small` 确实把 `cutoff_len` 从 2048 砍到 1024，但本任务
的样本**最长只有约 326 token**（每条音频恒为 **250** 个 audio token，min=median=max；
角色文本最长 229 字符 ≈ 76 token），远低于 1024 —— 截断根本不会发生。
实证也对上了：新增的 `c1024/4×8/seed42` 臂 F1 = **0.1805**，与 c2048 的 0.1727 差
**+0.008**，落在噪声内。

**③ 5 个块的差异方向相反。** 两套训练集 2,095/2,100 共享（messages 全同、抽检 80/80
音频 md5 一致）；v2 独有的 5 块正是它**泄漏进评估集**的那 5 块 —— 泄漏对 v2 有利，
解释不了 own10 更高。

**④ 8×4 在本卡上无法做干净对照。** 2026-09-13 实测 own10@8×4 在 **step 131/132**
报 `CUBLAS_STATUS_INTERNAL_ERROR`（4×8 的对照臂 12 分钟干净跑完），与基础设施笔记里
记录的失败签名逐字一致。但 f8c_v1 在 2026-08-28 用 8×4 **跑成功过** —— 所以 8×4
不是"不能跑"而是**抽奖**，不能当作可复现配置。（所以"micro-batch 移动 0.05"这个推论
既没有依据、在本机也无法验证。）

**⑤ ~~而 run-to-run 噪声其实很小~~。** 把三条 own10 臂放在一起（c1024 已证等价于 c2048）：

| run | 配置 | F1 |
|---|---|---|
| own10 | c2048 / 4×8 / seed 42 | 0.1727 |
| own10_s1234 | c2048 / 4×8 / seed 1234 | 0.1887 |
| own10_c1024 | c1024 / 4×8 / seed 42 | **0.1805** |

~~**三次复现：均值 0.181、标准差 0.008、极差 0.016。** 而 v2 的 0.1203 低于该簇均值
约 **7.6 个标准差** —— 远远落在 run-to-run 噪声之外。~~

> 🚫 **本条 ⑤ 已整体推翻（2026-09-14，§7.4）。** 这"三次复现"里有一次是 c1024 —— 它与
> seed42 **共享同一个种子**，只是换了个已被证明为空操作的 cutoff，所以它**不是独立
> 重跑**，把它算进"复现"本身就把方差估小了。真正的独立点只有 2 个。
> 补到 7 个独立种子后：**均值 0.149、SD 0.031、极差 0.096**，v2 只偏离均值
> **0.9 个 SD**；而且 own10 自己有一跑（seed 55555 = 0.0930）**比 v2 还低**。
> "7.6 个标准差"是把 2 个点的差当成 SD、又用 3 个点估方差得到的**伪异常**。

> ⚠️ ~~**结论：这 0.052 是真实的，但原因未明。**~~ → **已修正为：这 0.052 就是本管线
> 的普通 run-to-run 波动，无需任何额外解释（§7.4）。** ~~不要把 f8c_v2 的 0.127 与 G1
> 各臂的数字当作可直接比较的两个数~~ —— **v2 与 own10 是可以比的**，只是**单次 run
> 之间本来就差着 ±0.03 甚至更多**，所以任何**单次 run 对单次 run** 的 0.05 量级比较
> 都不足以支撑结论。§7.1 之所以只能算上界，原因不是"未识别的 run 级差异"，
> 而是**它把一次普通波动读成了系统差异**。
>
> 这一段排查的**否定性结论依然成立且有用**：micro-batch 确实相同、cutoff_len 确实是
> 空操作、5 块数据差异方向确实相反 —— 只是它们当时都在为一个不存在的问题服务。

**顺带（对论文很重要）**：v1(0.124) 与 v2(0.127) 的训练集都**泄漏了 5 个评估块**，
f8c_v3 泄漏 1 块；G1 两臂与 f9 为 0。已发表的 v1/v2 数字需要按"无泄漏"重测，
或至少在论文里声明。

### 7.4 补 5 个种子后：噪声下限翻倍，而 §7.3 的"谜"消失了（2026-09-14）

§7.3 是拿**三个点**（其中还有一个不是独立重跑）估出来的方差，据此把 v2 判成"7.6 个
标准差的异常"。既然是**样本量**的问题，办法就只有一个：再跑。2026-09-13 夜起补了
5 个独立种子（7 / 2024 / 3407 / 31337 / 55555），own10 臂共 **7 次独立重跑**：

| run | 种子 | F1 | P | R | tp / 26 |
|---|---|---|---|---|---|
| own10 | 55555 | **0.0930** | 0.0583 | 0.2308 | 6 |
| *f8c_v2（对照，非本臂）* | — | *0.1203* | *0.0748* | *0.3077* | *8* |
| own10 | 2024 | 0.1295 | 0.0796 | 0.3462 | 9 |
| own10 | 7 | 0.1429 | 0.0859 | 0.4231 | 11 |
| own10 | 31337 | 0.1587 | 0.1000 | 0.3846 | 10 |
| own10 | 3407 | 0.1600 | 0.1010 | 0.3846 | 10 |
| own10 | **42（主实验）** | 0.1727 | 0.1062 | 0.4615 | 12 |
| own10_c1024（参考） | 42 | 0.1805 | 0.1121 | 0.4615 | 12 |
| own10 | 1234 | 0.1887 | 0.1128 | 0.5769 | 15 |

**own10 的 run-to-run 分布（n = 7 次独立重跑）**：

|---|---|
| 均值 | 0.1494（95% CI [0.1266, 0.1694]） |

**新一次重跑的 95% 预测区间 = [0.0673, 0.2314]，v2 落在区间内**。

§7.3 那 0.052 的"差距"，在 7 个点面前**缩水成了一次普通波动** —— **无需任何解释**。

**② §7.2 的 0.016–0.024 低估了约一倍。** 那是 2 个点之差，不是 SD。SD 的点估计
0.031 本身还带 `[0.020, 0.070]` 的 CI —— n=7 时 SD 仍有 ±29% 的相对不确定度，

少部分换块**。所以"换种子"既不是整体平移，也不是完全换一批 —— 是**那 11 个摇摆
事件在掷硬币**，每个约值 1/26 = 0.0385 recall。

> 分析输出）。它们**不随种子变化**，所以不是运气问题：可能是标签边界与评估窗口的
> ±0.5s 不匹配、音频本身没有可辨的 backchannel、或转写/切分有误。查清这 9 个比再跑
> 10 个种子更有价值 —— 它同时会抬高所有臂的绝对 F1，且是**一次性**的收益。
>
> ✅ **2026-09-16 已查清，见 §7.5**：三种独立原因，最主要的一种是**评估集构造 bug**
> （GT 窗口横跨 chunk 边界，声学证据在相邻块里），**没有一块是标签标错**。

> ⚠️ **对 §7.3 的总评**：那一整节排查的**否定性结论仍然有效**（micro-batch 确实相同、
> cutoff_len 确实是空操作、5 块差异方向确实相反），但它是在**追一个不存在的幽灵**。
> 真正的教训不是"别比较来源不同的 run"，而是 —— **用 2–3 个点估 SD，会把随机波动
> 包装成异常，然后你会花一整天去解释一个不存在的东西。** 遇到"离群值"时，先问
> "我的 SD 是用几个点估的"，再问"它为什么离群"。

### 7.5 那 9 个"从未命中"的块查清了：**三种不同原因，没有一个是"标签错"**（2026-09-16）

§7.4 的 💡 猜"更像标签/音频问题"。查完发现这个猜测**半对半错** —— 确实不是模型的锅，
但也**不是标签错**，而是三种彼此独立的机制，其中最主要的两种属于**评估集构造**。

分析脚本：`ari_g1_never_hit.py`（块级画像）、`ari_g1_pred_times.py`（打预测时刻）、
`ari_g1_boundary.py`（全 25 块量化）、`ari_g1_prior_probe.py`（位置先验检验）。

#### 原因 A：GT 窗口横跨 chunk 边界（3/9）—— **本质不可答**

| 层 | n | 窗口横跨边界 |
|---|---|---|
| 总是命中 | 5 | **0（0%）** |
| 时灵时不灵 | 11 | 3（27%） |
| 从未命中 | 9 | **3（33%）** |

6 个横跨边界的窗口（`min_inside` = 窗口落在块内的比例）：

| chunk | 层 | min_inside | GT 窗口 |
|---|---|---|---|
| `02053f7c_ch1_t235` | never | **0.098** | (-0.46, 0.05) |
| `0e9c68be_ch1_t2520` | swing | 0.145 | (-1.89, 0.32) |
| `0736fa95_ch1_t1105` | never | **0.174** | (-0.76, 0.16) |
| `0203bb21_ch0_t765` | swing | 0.385 | (-0.72, 0.45) |
| `071cf0a9_ch0_t245` | swing | 0.386 | (-0.86, 0.54) |
| `0d4a795e_ch1_t540` | never | **0.851** | (9.14, 10.15) |

前两个尤其致命：`02053f7c` 的窗口**只有 9.8% 在块内**，`0736fa95` 只有 17.4% ——
声学证据几乎全在**相邻块**里，却要求模型在本块内报出时刻。这不是模型能力问题。
对照组 5 块**全部完整落在块内**（`min_inside` 中位数 1.000），这不是巧合。

#### 原因 B：模型找到了事件，但那个事件被标成 `realized=None`（1/9）

`0d4a795e_ch1_t540` 里有两个 BC 事件：GT 在 (9.14, 10.15)（又是边界块），
另一个 `realized=None` 在 (4.34, 5.16)。模型预测 **5.00s（s42）/ 4.80s（s7）—— 
两个种子都正落在那个非 GT 事件上**（可命中区间 [3.84, 5.66]）。该事件不计 GT，
于是这次**正确的听觉判断被记成 FP**。

> 这正是 **F3 那个发现**（`realized=None`/"停顿内"里有 44% 人耳听到了重叠）在指标上的
> 投影：模型听到了一个真实的 BC，标签说"这不是 BC"，指标扣它的分。

#### 原因 C：剩下 5/9 是**真·难例** —— BC 太弱

先排除一个诱人的解释。never 组有 4 个块的预测落在 **8.2–8.8s**，看着像"没证据时的
刻板落点"。于是拿 **40 个完全无 GT 的块**测了一遍（`ari_g1_prior_probe.py`）：

- 25/40 答 `no backchannel`，其余 15 个预测**分布是散的**（中位数 4.20s，
  范围 0.40–8.20s）；落在 8–9s 的只占 **13%**，而均匀分布期望就是 10%。
- **没有位置先验。** 那 3 个 8.x 不是退化输出，是模型真在报别的东西。

真正的区分量是**响度**。GT 窗口 RMS ÷ 全块 RMS：

| 层 | n | 中位数 | 范围 |
|---|---|---|---|
| 总是命中 | 5 | **4.72** | 1.03 – 10.31 |
| 时灵时不灵 | 11 | 1.49 | 0.77 – 9.62 |
| 从未命中 | 9 | **1.47** | **0.43** – 4.88 |

**总是命中的事件在块内是 4.7 倍响度的显著事件；从未命中的中位数只有 1.47，
9 个里 4 个甚至比块平均还安静（< 1.0），而对照组最低也有 1.03。** 完全没有重叠。

#### 结论：`never` 这一层的真实含义要改写

| 原判（§7.4） | 查清后 |
|---|---|
| 9 块"与种子运气无关，更像标签/音频问题" | **3 块评估集构造**（窗口横跨边界）+ **1 块标签口径**（`realized=None` 吃掉了正确的检测）+ **5 块真·难例**（BC 信噪比低） |

**没有一块是"标签完全标错了"。** 对 F1 的含义：

1. **原因 A 是纯评估集 bug，可一次性修掉** —— 把 `min_inside < 1` 的窗口在评估时剔除
   （或要求窗口中心落在块内）。这会**同时抬高所有臂的绝对 F1**，且对两臂是同一批块的
   同一批事件，**不改变臂间比较的公平性**。
2. **原因 B 不能靠改评估集解决** —— 它要等 F3 那条线（`realized` 口径是否该扩成
   "人耳听到的重叠"）有结论。在那之前，这 1 个 FP 属于**指标与人类感知不一致**，
   不是模型错。
3. **原因 C 就是噪声的来源本身** —— 与 §7.4 那 11 个摇摆块同源：BC 越弱，越靠运气。

> 💡 **对"扩评估集"的影响**：本节那 9 个块里有 **3 个是边界伪影**；把口径放到**全部**
> 25 个 GT 块上重算（§7.7 c），横跨边界的真值事件是 **6/26 = 23%** ——
> **近四分之一的事件本来就不可能答对**，足以让 F1 的绝对值和排序都失真。
> **扩评估集时务必加一条"窗口必须完整落在 chunk 内"的过滤**，否则只是把同样比例的
> 伪影按比例放大。
>
> ✅ **已实现（2026-09-16）**：`bc_windows(require_inside=True)` + `--require-inside`，
> 扩集与旧集**两套评估全程开启**，见 §7.7。

### 7.6 配对设计：给 mixnorm 补齐同批 7 个种子（2026-09-16）

**动机.** §7.4 只把 own10 描到了 7 个种子，mixnorm 仍只有 2 个，ΔF1 的误差棒是**借
own10 的方差**算的。而且 LLaMA-Factory 的 `seed` 同时决定**权重初始化与数据打乱** ——
所以让两臂跑**同一批种子**，每一对就共享除观测空间外的一切，理论上 d = mixnorm − own10
应当消掉"这个种子运气好不好"这一项，给出更紧的误差棒。

**做法.** 给 mixnorm 补上 own10 已有的同 5 个种子（7 / 2024 / 3407 / 31337 / 55555），
凑满 **7 对**同种子。`G1_ARMS=mixnorm G1_MORE_SEEDS="7 2024 3407 31337 55555"
bash scripts/g1_seeds_extend_arm.sh`。

### 7.7 修边界过滤 + 扩大评估集（2026-09-16 起，✅ 已完成）

§7.5 查出旧 300 块集里 **6/26 = 23%** 的真值事件本质不可答（初稿只数了那 9 个块内部
的，写成 11.5%，见 (c) 的更正），§7.6 又算出 n=7 的 MDE (0.060) 比待检效应 (0.034)
还大 —— 两条证据指向同一个动作：**把评估集修好并做大**。本节记录这件事。

#### (a) 边界过滤：已实现

`bc_windows()` 新增 `require_inside` 开关（`ari_g1_common.py`），只保留
**完整落在 `[t0, t0+chunk_s]` 内**的真值窗口；`ari_g1_eval.py` 加 `--require-inside`，
并把**丢弃了几个横跨边界的窗口**打进日志与 json。默认关闭，所以既有脚本行为不变。

**两臂评的是同一批块、同一批事件，所以这个过滤不影响臂间公平性**，只抬高绝对 F1。

#### (b) 顺带发现：训练集与评估集的事件流行率差了 10 倍

这是修评估集时才注意到的，**独立于边界问题**，而且可能比边界问题更重要：

| | 块数 | 含 ≥1 个真值事件的块 | 流行率 |
|---|---|---|---|
| **训练集** | 2100 | 1817 | **86.5%** |
| **冻结评估集** | 300 | 25 | **8.3%** |

原因不难找：训练集是 `select_train_chunks` **按事件富集**选出来的（正例 3/4、
硬负例 1/8），而评估集是 F8 任务留下的**随机**块样本。于是在一个事件流行率
86.5% 的数据上训练，却在一个流行率 8.3% 的集合上评估 —— **精度那一项尤其失真**：
模型在 300 块里报了约 113 个事件，只有 26 个是真的，而"随便指一个块"的先验命中率
本来就只有 8.3%。**评估集测的是一个模型几乎没见过的分布。**

> 口径已交叉验证：用 `bc_windows` 重算 300 个评估块的 `n_gt`，与既有
> `g1_eval_*.json` 里的 `n_gt` **300/300 完全一致**，所以上表不是匹配口径的产物。

#### (c) 扩集：g1-E2（1600 块 / 1640 个事件）

| + 旧 300 × 14 | 1.6 h |

密集块并没有显著变慢 —— 生成被 `max_new_tokens=128` 截断，而"no backchannel"
本来就只差几个 token。**这种"想当然会更慢"的地方值得花 5 分钟测一下**：
差 2 倍就会让 12 h 的排期变成 24 h、顶穿作业窗口。

#### (f) 两个会静默毁掉这次运行的坑（已修）

扩集比旧流程多两个"不看产物根本发现不了"的陷阱，都是**跑完几小时才暴露**的类型：

1. **`--n-eval` 默认 300 的截断**：`ids = load_ids_file(ids_file, args.n_eval)`
   —— 传了 1600 个 id 的清单，却因为 `n_eval` 默认 300 而**只评前 300 块**，
   json 照样生成、`f1` 照样好看，只是数字悄悄退化成旧集的口径。
   改成默认 0（不截断），冻结集仍走 `or 300` 保持既有行为。
2. **`--manifest-from` 用错集合直接 KeyError**：扩集的 1600 个 id 不在旧 manifest
   里，旧 300 个 id 也不在扩集 manifest 里。原脚本对两套评估集都写死
   `--manifest-from .../g1_e2/mixnorm`，跑到旧集时会崩。
   改成按 stage 取 manifest（`mani()`）。

两条都补了**按内容核对**的断言（核 `n_chunks` 而不是只核文件是否存在）——
"文件在"不等于"评对了集"，这正是既有纪律"以产物为准"要再往前一步的地方。

**方差分解**是这次的重点：把 `SD(跨种子)` 与 `SE_eval`（固定权重只重采样 chunk）
对比，就能知道 run-to-run 波动里**多少是"评估集抽样"、多少是"训练随机性"**。
若前者是主项，说明扩评估集就能救 G1；若后者是主项，说明还得加种子 ——
**这个分解决定了下一步该投哪边**，而且它不需要任何新训练。

## 8. 结论与 caveat

### 结论

**没有证据表明"观测对方"有益。** 完整测量（7 对同种子配对，§7.6）：

| 量 | 值 |
|---|---|
| ΔF1 均值 | **−0.0336** |
| SD(d) / SE | 0.0476 / 0.0180 |
| **95% CI (t₆)** | **[−0.0776, +0.0104] —— 含 0** |
| 置换检验 p / 符号检验 p | 0.094 / 0.0625 |
| 方向 | 6/7 个种子 ΔF1 < 0；精度 6/7 更低、召回 5/7 更低 |

**方向一致，但幅度测不准** —— 点估计是负的，CI 含 0，置换检验不显著。
而且**这个实验本来就没有能力判定它**：n=7 的最小可检出效应是 **0.060**，
观测效应 0.0336 只有它的 **56%**（§7.6、caveat a）。

### 结论 ②（2026-09-17 新增）：**但"混合观测空间让训练不稳"是站得住的**

§7.7 扩集（1600 块 / 1640 事件）之后，均值仍然判不实，但**方差的差异非常清楚**：

| | own10 | mixnorm |
|---|---|---|
| F1 均值（E2） | 0.4877 | 0.3637 |
| **F1 跨种子 SD** | **0.0236** | **0.1020** |
| F1 极差 | [0.455, 0.519] | **[0.245, 0.524]** |

**方差比 18.6 倍**（F(6,6) = 18.64）—— 而且**不是靠离群点撑的**：

- **精确置换检验**（把 14 个 F1 值按全部 C(14,7)=3432 种方式分臂）：**p = 0.0026**；
- **留一法**：去掉任意一个种子，F 仍在 **[9.87, 27.05]** 区间内。

**注意 mixnorm 的上界（0.524）比 own10 的最高分（0.519）还高。** 所以它不是
"稳定地差一点"，而是**同一套数据、同一批种子、同一套超参，只换观测空间，
有时训得一样好，有时直接崩**（seed 42 只有 0.245）。

这条**比均值结论更值得写进论文**：它说明单声道混合带来的不是"信息少了多少"，
而是**优化景观变差 / 训练对种子变得敏感** —— 一个可复现、可迁移的观察。

> **为什么旧评估集看不见这个？** 旧集只有 20 个事件，所有臂都被挤在 0.08–0.17
> 的窄带里（地板效应），两臂 SD 几乎相等（F = 0.61，p = 0.57）。
> **"方差小"不等于"评估集好"** —— 旧集方差小是因为它分辨不出东西（§7.7 d ④）。

> ⚠️ **一个曾经的过度解读，记在这里**：本分析在只有 **5 对**种子完成时先算过一次，
> 得到 ΔF1 = −0.0525、CI [−0.076, −0.029] **排除 0**，一度被当作"推翻了不显著的
> 判读"。**补上剩下 2 个种子后 CI 立刻变成含 0。** 与 §7.3 的幽灵同源：
> **样本不完整时算出的统计量不是"提前看到的结论"，只是噪声。**

> ⚠️ **另一个必须记住的方法学点**：第 4 节那种配对 bootstrap 只重采样 chunk、**把训练
> 好的权重当作固定**，因此是**反保守**的 —— 它给种子 1234 的 ΔF1 报了 P=0.004 的
> "显著"，而按种子间变异衡量根本不显著。**报告效应时必须以 run/seed 级变异为
> 标尺**，否则会把噪声写成发现。本文档 §4 的 CI 只应作参考，不应作为显著性依据。
> （本文档早期版本曾用 √(0.031² + 0.017²) ≈ 0.036 当两臂差的标准误 —— 那是把两臂
> 当独立样本、且 0.017 只由 2 个点估出，**已废弃**，见 caveat a。）

前提与操纵本身仍由**三条独立证据**支撑：

1. **前提成立**（第 3 节）：本人声道里确实没有对方 —— 对方说话帧的能量比静音帧
   还低 7.1 dB，包络互相关中位 −0.373，仅 0.13% 的段 >0.5。
2. **操纵有效**（第 5 节）：在承载真值事件的 25 个块上，对方占 mix 能量中位
   39.2%，残差与对方声道相关 1.0000（25/25）。
3. **噪声下限**（第 7.4 / 7.6 节）：同臂只换种子，7 次重跑给出 SD 0.031 / 极差 0.096；
   效应量（0.033）比这个极差还小，所以**测不准**。曾指望"同种子配对"能压掉这份
   噪声，**实测不能**（两臂 r = −0.29，§7.6）—— seed 级方差在换观测空间后不可配对抵消。

因此正确的表述是：**未发现"观测对方有益"的证据**，而不是"证明对方信息无用"，
更不是"证明对方有害"。前者与后两者的区别在 caveat a（欠功效）与 caveat b
（单声道混合丢失了"谁是听话人"）。

### Caveat

**a. 欠功效（最重要）—— 2026-09-17 已查明，且已排除"扩评估集"这条出路。**
第 7.7 节把评估集从 **26 个真值事件扩到 1640 个**并重跑 7 对，结论是：

- **扩集没有带来功效**：MDE 反而从 0.0384 **升到 0.1328**（因为 SD(d) 涨得更快）；
  观测 |ΔF1| 仍是 MDE 的 93%，**依旧判不实**。
- **但查清了波动来自哪里**：把"评估集抽样"与"训练随机性"分开 ——
  旧集上评估集抽样占总方差 **41%**，扩集后只剩 **1%**。
  即 **run-to-run 波动几乎全部来自训练随机性**。
- **所以"再扩评估集"这条路已经走到头**：要判 0.03 的均值差需要 **≈137 对种子**，
  0.02 需要 ≈309 对 —— 机时上不可行。

主要能主张的仍然只有**方向**：两套评估集上 ΔF1 都是负的，但符号检验分别只有
**5/7（p = 0.23）** 与 6/7（p = 0.063），且两套的**留一法都不干净**。
达不到"证明有害"。要给出强陈述应换用**更稳的指标**（如帧级 PR-AUC），
而不是继续加种子或扩评估集。

> ⚠️ **一处已更正的判读**：§7.5 初稿称"旧集 11.5% 的事件横跨边界"，实测全量是
> **6/26 = 23%**。这个更正让旧集的边界过滤效果比原先认为的更强（SD(d) 0.0476 → 0.0309），
> 也让旧集在过滤后**勉强**跨过显著线（CI [−0.0626, −0.0054]）——
> 但**这个"显著"去掉除 55555 外任何一个种子就消失**，不应采信（§7.7 d ③）。

> ⚠️ **不再使用**旧的"两臂差标准误 ≈ √(0.031² + 0.017²) ≈ 0.036、−0.033 是 0.9 SD"
> 这一算法 —— 它把两臂当**独立样本**，且其中 0.017 是**只用 2 个点**估出的 mixnorm SD。
> §7.6 的配对实测取代了它。

**b. 单声道混合丢失了"谁是听话人"。** mixnorm 把两个说话人**求和进一路单声道**，
模型无法区分哪一路是"我"、哪一路是"对方"。所以"给了也没用"**可能**只是因为混杂
本身破坏了信息，而不等于"对方信息无用"。要真正证伪观测空间假设，需要**双声道
（立体声）或显式分离**的输入，让模型能归因。这是本实验最主要的未竟之处。

**c. v2 对照 —— ✅ 已闭合（2026-09-14）。** ~~§7.2 的同臂换种子重复给出了干净的噪声
测量（0.016–0.024），所以 §7.1 的 0.052 只能当上界用。但 §7.3 的排查推翻了"这 0.052
来自 micro-batch 或 cutoff_len"的解释，也没有找到替代解释：那 0.052 是真实的，成因
未明~~ —— **§7.4 用 7 个独立种子证明：那 0.052 就是普通 run-to-run 波动，v2 的 0.1203
只偏离均值 0.9 个 SD、落在 95% 预测区间内，own10 自己还有一跑比它更低。无需解释，
本项关闭。** 补充一条仍然有效的告诫：**单次 run 对单次 run 的比较，在 0.05 量级上
不可靠** —— 这不是 v2 特有的问题，是所有臂共有的。

**d. 已发表数字存在训练/评估泄漏。** f8c_v1(0.124) 与 f8c_v2(0.127) 的训练集各
**泄漏了 5 个评估块**，f8c_v3 泄漏 1 块；G1 两臂与 f9 为 0。v1/v2 需按"无泄漏"
重测，或至少在论文里声明。**注**：泄漏方向对 v2 有利，所以它不解释 own10 的优势。

**e. 标签本身的稀疏性可能是更根本的瓶颈。** X2-Turn 给 85.5% 的帧打"双方静音"、
仅 0.02% 打"双方都在说"（第 3 节）。若 BC 的判据在这个标签体系里本就稀薄，那么
无论给模型看哪一路声道，上限都被标签定义本身压住了 —— 这与用户此前的质疑
（"人工判定的 text 都太短了…这样的标注模型学不到东西"）指向同一个方向，
且比观测空间更值得下一步投入。

**f. 方差比检验的口径（2026-09-17 新增）。** §8 结论 ② 用的 F 检验（F(6,6)=18.64）
形式上是**两独立样本**的方差比检验，而两臂其实是**配对**的（同种子）。这里可以这样用，
是因为实测两臂逐种子相关 **r = −0.098 ≈ 0**，配对没有带来任何共享变异；但要如实说明
这是一个近似。**更强的是那条分布无关的检验**：把 14 个 F1 值按全部 C(14,7)=3432 种
方式重新分臂，得到精确置换 **p = 0.0026**，它不依赖正态假设。留一法 F ∈ [9.87, 27.05]
说明结论不由任何单个种子决定。

**g. mixnorm 不稳的成因未查。** 结论 ② 确立了"方差大"这个现象，但**没有**解释
为什么。可查的方向：混合后音频的动态范围/削波、`realized` 事件在两臂的分布差异、
以及优化层面的梯度尺度。**在给出机制之前，不应把"不稳"写成"更差"。**

**h. 两套评估集的绝对 F1 不可比。** E2 事件流行率接近 100%，旧集 8.3%；
E2 上 own10 均值 0.4877、旧集 0.1368。**这个差距几乎全部来自流行率，不来自模型变好。**
引用任何绝对值时必须写明是哪一套集。
