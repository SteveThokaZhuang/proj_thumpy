## 1. 为什么要做

§7.2 的结论是：配对 ΔF1（own10 − mixnorm）= **+0.0340**，但这个数**判不住**。
卡住它的不是种子数，是**块抽样**那一项方差：

| 方差源 | 量级 | 随评估集增大 |
|---|---|---|
| SE_seed（跨种子） | 0.0117 | **不缩** —— 它是模型的性质 |
| SE_chunk（块抽样） | 0.0198 | 按 1/√k 缩 |
| 合并 SE = hypot | **0.0230** | → t = 1.48 |

所以要改判，唯一的路是把 SE_chunk 压下去，而这**不需要重训** ——
换一套更大、且现有 14 个 adapter 都没见过的评估集即可。

## 2. 先纠正 §7.5 里那个池子数字（已作废）

§7.5 写的是「82544 块 / 4982 事件 / 5.8% 正例」。**这个数是错的**，
而且错法很隐蔽：它只存在于 `ari_g1_eval_power.py:158-159` 的一句
**硬编码 print 字符串**里，脚本从没算过它 —— 所以它不会被任何复跑纠正。

实测下来它对应的是 **`--used g1_ids.txt` 只排除了 2400 块**、且**没有做
时间排除**的口径。换句话说，那个数字是 **E2（1600 块）还不算「已用」的时候**
算的，之后一直没更新。

正确的枚举（`scripts/ari_g1_eval4_ids.py` 实跑）：

| 口径 | 块数 | 事件 | 正例率 |
|---|---|---|---|
| `used=g1_ids` only，无时间排除（**旧 §7.5 的数**） | 82544 | 4982 | 6.04% |
| `used=g1_ids`+`eval2`，无时间排除 | 80944 | 3342 | 4.13% |
| **`used=` 两者 + 时间排除（本次实际采用）** | **76425** | **3000** | **3.93%** |

**教训**：把结论数字写进 `print` 字符串而不是让它由脚本算出来，
等于给这个数字上了一道免于复现的锁。§7.5 表格里
「k=4 → ~80 事件」的外推就是被这个 4982 带偏的 ——
按 6.04% 估，1200 块确实约 72 个事件；实际只有 **43 个**（见 §5）。

## 3. 一个之前一直没查的构造问题：块之间**共享音频**

`ari_g1_eval2_ids.py`（E2）与旧 300 集都只保证了**块 id 不相交**。
但块是按 **5 秒步进**生成的，而 chunk 长 **10 秒** —— 于是相邻两块
**共享 50% 的音频**：

```
t=450  [========================]        训练块
t=455       [========================]    评估块  ← 5 秒是同一段音频
```

实测这个不是边角情况：
- `g1_ids.txt` 里大量 `t=45,50` / `295,300` / `320,325,330` 这样的成对块
- E2 里 `0020a0c5_ch0_` 的 t = 275, 455, 460, 510, **515**, 535, **540**, 1280, **1285**

**量化结果**（每套评估集里，与那 2100 个训练块时间重叠的块占比）：

| 评估集 | 重叠块 | 占比 |
|---|---|---|
| 旧 300（`g1_eval_ids.txt`） | 9 / 300 | 3.0% |
| **E2（`g1_eval2_ids.txt`）** | **184 / 1600** | **11.5%** |
| **k=4（`g1_eval4_ids.txt`）** | **0 / 1200** | **0.0%** |

E2 有 **超过 1/9 的块与训练音频共享 5 秒**。这不推翻 E2 的结论
（臂间配对比较里，污染对两臂同向作用，主要效果是把两个臂的 F1 一起抬高、
可能压缩差值），但它是一个此前没被记录的效度折扣，**E2 的绝对 F1 不宜
当作泛化性能来读**。k=4 集按构造排除了这一层。

> 注：池子里有 4519 个候选块（占池外 80944 的 5.6%）因这条被丢弃。
> 丢得**不是均匀的** —— 被丢的是训练块的时间邻居，而训练块是**按「含事件」
> 挑出来的**（`g1_ids.txt` 正例率 69.9%），所以这些邻居也偏事件密集。
> 这正是池子正例率从 6.04% 掉到 3.93% 的原因。这不是 bug，
> 是「排除污染」必然带来的口径变化，但报流行率时要说明它。

## 4. 选块脚本：与 E2 的三点差别

`scripts/ari_g1_eval4_ids.py`（由 `ari_g1_eval2_ids.py` 改写）：

1. **不要求「块内至少 1 个事件」** → 自然流行率（3.93%）而不是 100% 正例。
   E2 的 100% 正例率正是 §3.3 那个方差伪影的来源。
2. **排除时间重叠**，不只排除 id 相同（§3）。
3. **每个 (session, ch) 内部先用固定 RNG 打散再轮转取样**。
   E2 的候选按 t 升序排，轮转取样等于**每个会话都只取最前面几个块**，
   评估集会挤在每个会话的开头；打散后块在会话内铺开。

## 5. 功效预测：k=4 能不能判定？**能，但只是刚够**

先做了一次**零 GPU 成本**的预判 —— 因为 §7.5 的成本表是建立在
「~80 事件」上的，而实测只有 43 个，若不先算清楚就白烧 7.8 小时。

`scripts/g1_eval4_predict.py`：拿**已有的**旧 300 块 × 14 adapter 逐块
tp/fp/n_gt，对 k ∈ {150, 75, 37} 抽**跨 14 个 adapter 共用**的块子集
（共用是关键：块抽样是跨种子共有的方差源），测配对 ΔF1 的 SD，
再拟合标度指数。

**基准口径必须用 `filt`**（边界过滤后）—— 它才复现 §7.2 的
ΔF1 = +0.0340、SE_seed = 0.0117。用未过滤的 `plain`（SE_seed = 0.0180）
会把 t 系统性压低到 1.8 左右，得出「k=4 不值得跑」的**错误**结论。

```
SE_chunk ∝ k^(-0.672)        (在 k=150/75/37 上拟合, 指数稳定)
按块数外推 (1200 块):   SE_chunk = 0.0052  -> 合并 SE = 0.0128  ->  t = 2.66
按事件数外推 (43 事件): SE_chunk = 0.0078  -> 合并 SE = 0.0141  ->  t = 2.42
天花板 (SE_chunk -> 0):                                        t = 2.91
```

**预测 t = 2.42 ~ 2.66**，对照现状 t = 1.48。跨过 2，所以值得跑。

两点保留：
- 这是**预测不是结论**，k=4 跑完必须重新报，并复核流行率与 F1 量级。
- 拟合范围是 k=37~150，外推到 1200 是 8~32 倍的外推。
  指数本身在三个点上稳定（−0.708 / −0.646），但仍是外推。

> 顺带记录一个**不能用的**判据：曾想在 k=200 处直接比较
> 「旧 300（17 事件）vs E2（205 事件）」的 SE_chunk 来判驱动量，
> 结果是 E2 反而**更大**（0.0267 vs 0.0142）。但 E2 的 F1 量级高 3–7 倍，
> 绝对噪声随量级走，比出来的是量级差不是事件数差。**该对比作废**，
> 判驱动量只能用同一集合内的标度指数。

## 5.5 ⚠️ 对 §5 预测的**流行率修正**（结果落地前完成，预登记）

**§5 的 t = 2.42~2.66 大概率是错的，而且是系统性偏乐观。**

### 错在哪

§5 的做法是：在旧集上拟合 `SE_chunk ∝ k^−0.672`，外推到 1200 块，
**同时把 ΔF1 固定在旧集的 +0.0340** —— 只让噪声缩，不让信号动。

但 k=4 集是**自然流行率**（3.58%），旧 300 是 6.33%。k=4 首个产物
已经把这个差别摆出来了（own10 ds=42）：

| | precision | recall | F1 |
|---|---|---|---|
| 旧 300（filt） | 0.088 | 0.500 | **0.1504** |
| k=4（e4） | 0.048 | 0.442 | **0.0866** |

**recall 几乎没动，precision 腰斩。** 模型的正例率基本恒定（~35%），
base rate 减半，precision 就跟着减半 —— 这是流行率效应，
不是模型变差。**而同一个流行率变化既压噪声、也压信号**，
§5 只算了前者。

### 修正方法

旧集的逐块 tp/fp 里天然存着**负例块的误报分布**（281 块中 100 块有误报，
均值 0.356/块），正是自然流行率集里占 96% 的那部分。故可直接把旧集的
两类块当经验分布，按目标流行率**分层重采样**（`scripts/g1_e4_prevalence_predict.py`）：

    每个槽位独立地：以 p_pos 概率从「正例块池」抽，否则从「负例块池」抽

**同一份重抽块索引用在全部 7 个种子上**（块抽样是种子间共有的方差源，
各自独立重抽会把它当噪声约掉，SE_chunk 系统性偏小）。

### 自检（同代码在已知答案上跑）

| 量 | 得到 | 期望 |
|---|---|---|
| SE_chunk @ K=300, p=6.33% | **0.0199** | 0.0198 ✅ |
| ΔF1 @ 同口径 | **+0.0343** | +0.0340 ✅ |

### 迁移性检验（关键，且是样本外）

整套修正依赖「k=4 的块与旧集的块逐块行为可比」。拿已经到货的
adapter 当场验 —— 用**纯旧集数据**推出的 F1 分布，对实测值：

| | 模拟 | 实测 | 差 |
|---|---|---|---|
| own10 ds=42 | 0.0909 | 0.0866 | +0.0043 ✅ |
| **mixnorm ds=42** | 0.0661 | 0.0811 | **−0.0150 ❌** |

> 🔴 **检验只过了一半，而且失败的那一半正好是要紧的那半。**
> 单看每条臂，own10 差 0.004 还算能接受；但 **ΔF1 是两条臂之差，
> 两侧的误差在差值里是相加的, 不是相消的** —— 于是 sim 的 ΔF1
> 比真实 ΔF1 **系统性高估约 0.019**。
> ⇒ **下面那个 +0.0211 本身就偏高，应视为上界**，不是点估计。
> （教训：用模拟预测**差值**时，必须分别在**每一条臂**上验迁移性；
> 只验一条臂、或只验一个总量，都会漏掉这种误差叠加。）

### 修正后的预测

```
SE_chunk(1200 块, 自然流行率) = 0.0081
合并 SE = hypot(0.0117, 0.0081) = 0.0143
预测 ΔF1                        = +0.0211   <- 注意它**也**缩了
t = 0.0211 / 0.0143             = 1.48      <- 和现状一模一样
```

**⇒ 修正预测：k=4 跑完 t 仍在 1.5 附近，不会跨过 2。**
噪声按预期缩了（0.0198→0.0081），但**信号同步缩了**（+0.0340→+0.0211），
两者几乎相消。§5 那个 2.42~2.66 是「只缩噪声」的产物。

> **已知偏差方向**：模拟从旧集的 **19 个正例块**里有放回地抽 42 个槽位，
> 而真实 k=4 是 **42 个互不相同的正例块**。有放回抽样的构成方差**更大**，
> 所以 0.0081 大概率**高估**了 SE_chunk、从而**低估** t。
> 幅度未量化。即真实 t 可能略高于 1.48，但**不足以**回到 2.42~2.66。

**怎么用这个数**：k=4 跑完后**先报实测 SE_chunk 与实测 ΔF1，再和上面对照**。
两条都要对（噪声缩了 **且** 信号缩了）才算修正成立；只中一条说明
机制判断有误，如实报出来，**不要用这个预测去替代实测**。

### 5.5b ✅ 定案对账：**ΔF1 命中，SE_chunk 没中**（2026-09-18 04:0x，**7 种子全量**）

> 🔓 **本节 01:0x 的版本用的是 5 种子口径**（当时 `mixnorm_s55555_e4` 未到）。
> 现在 14/14 全齐，**整节按 7 种子重写**；5 种子那几个数只在下面标出来做对照。
> 结论方向**没有变**，但所有数字都换过了。

§5.5 要求「两条都要对（噪声缩了**且**信号缩了）才算修正成立」。
全量到货，正式对账：

| 量 | §5.5 预测 | e4 实测（**7 种子**） | 5 种子时 | |
|---|---|---|---|---|
| `ΔF1` | +0.0211 | **+0.0210** | +0.0224 | ✅ **命中**（差 −0.0001） |
| `SE_chunk` | 0.0081 | **0.0097** | 0.0098 | ❌ 差 **+20%** |
| `t` | 1.48 | **1.896** | 1.96 | 高于预测，但**仍未跨 2** |

⇒ **信号那一半的机制成立**（流行率变了，ΔF1 确实缩了，而且缩到几乎逐位命中），
**噪声那一半没按修正走**。

> 🔑 **顺带一个必须说清的巧合**：ΔF1 命中到 **0.0001** 之内 —— 这**不等于**
> §5.5 的机制被验证。§5.5 预测的是「ΔF1 会落到 +0.0211」，而它是拿
> **上界**口径推的（迁移性检验只过一半，见 §5.6）。命中 0.0001 是**两组误差相消**的
> 结果，不是精度。**报的时候说「落在预测上」，不说「预测被证实」。**

#### 🔍 那噪声到底按什么缩？—— 答案是**总块数**，不是正例构成

| 缩放假设 | √因子 | 预测 SE_chunk | vs 实测 **0.0097** |
|---|---|---|---|
| 总块数 300→1200 | **2.000** | **0.0099** | ✅ 差 **2%** |
| 正例块 19→42 | 1.487 | 0.0133 | ❌ 差 37% |
| 真值事件 17→43 | 1.590 | 0.0124 | ❌ 差 28% |

实测缩放因子 **2.041**（5 种子时 2.020）⇒ 拟合指数 **−0.515**。
**`SE_chunk` 就是朴素的 `1/√(总块数)`。**

> ✅ **5 种子时的「临时口径」警告到此解除**：补上第 7 个种子后 `SE_chunk`
> 只从 0.0098 动到 **0.0097**（−1%），所以「`1/√总块数` 不是巧合」这个判断
> **站住了**。（当初那句「7 个齐了要复核」现在复核完了，写在这里。）

> 🔑 **这修正了 §5.5 的机制说法**：流行率修正对**信号**（ΔF1）有效，
> 但对**块抽样噪声**（SE_chunk）**没有额外效应** —— 噪声只认块数。
> 换句话说：噪声是**分母侧**（大量负块贡献的假阳性波动）主导的，
> 不是正例块的构成主导的。这也解释了为何按正例块/事件数缩放都差得远。

### 5.5c 🔴 但**收缩本身**没有被确立（2026-09-18 04:1x，`scripts/g1_shrink_test.py`）

**§5.5 的整套叙事是「自然流行率把 ΔF1 从 +0.0340 压到 +0.0210」。**
§5.5b 只对了「预测 vs 实测」—— 而**"预测命中"和"收缩存在"是两个不同的问句**：
一个预测可以在**什么效应都没有**的情况下命中（只要基线够稳）。
所以收缩必须**另外检验一次**，这一步之前**根本没做**。

**设计**：两套评估集评的是**同一批 7 个 adapter** ⇒ 天然配对，
用每种子自己与自己比（消掉 §5.6 那条 🔴 选择偏差）。

| seed | filt | e4 | Δ = e4 − filt |
|---|---|---|---|
| 42 | +0.0440 | +0.0055 | **−0.0385** |
| 1234 | +0.0497 | +0.0213 | **−0.0284** |
| 7 | +0.0535 | +0.0418 | −0.0117 |
| 2024 | +0.0327 | +0.0195 | −0.0133 |
| 3407 | +0.0442 | +0.0238 | −0.0204 |
| 31337 | +0.0485 | +0.0323 | −0.0161 |
| **55555** | **−0.0345** | **+0.0024** | **+0.0369** ⚠️ |

收缩 = **−0.0131**，**6/7 为负**。看着很像那么回事 —— 但：

| 口径 | t | p | 95% CI |
|---|---|---|---|
| (a) 只看种子（漏掉块噪声，**乐观**） | −1.44 | 0.200 | [−0.0352, **+0.0091**] |
| **(b) 种子 + 块（主口径）** | **−0.55** | **0.604** | [−0.0715, **+0.0454**] |
| (c) 符号检验（丢幅度） | — | 0.125 | — |

🔴 **⇒ 收缩未被确立。** 主口径是 (b)：
差值的块侧误差 = `hypot(SE_chunk(filt), SE_chunk(e4))` = `hypot(0.0198, 0.0097)` = **0.0221**。
（这个"独立相加"**不是假设**：脚本实测两套块集**重叠 0 块**，✅ 成立。）

> ⚠️ **一个种子（55555）单独就能把结论翻面**：它是唯一为正的配对差（**+0.0369**），
> 而它恰恰是 filt 上唯一的负号。**去掉它，收缩看起来就很干净** ——
> 这正是"别按结果挑点看"的教科书场景（memory: sd-from-few-points-manufactures-anomalies）。

> 🔑 **一个对下一步有用的结构性观察：比较的瓶颈现在在旧集那一侧。**
> 差值块侧误差 0.0221 里，**0.0198 来自 filt（300 块）**，只有 0.0097 来自 e4（1200 块）。
> ⇒ **任何"相对旧评估集变了没有"的主张，都被旧集的块噪声卡住** ——
> 把新集做大**救不了**这类主张，得把**旧口径**也放到大集上重评。
> （即：要问"流行率有没有让 ΔF1 变小"，需要一套 1200 块的
> **旧流行率口径**对照，而不是继续加大自然流行率那一侧。）
> 这条对**所有**跨集比较都成立，不只这一处。

> 📌 **对 §5 那套外推的含义**：§5 用 `SE_chunk ∝ k^−0.672`（在 k=150/75/37 上拟合）
> 外推到 1200 块得 0.0052 —— 而真实指数是 **−0.515**。
> 那条幂律是在**很小的 k** 上拟合的，外推 32 倍之后指数本身就不可信。
> （实测端：0.0097 比"按块数"预测的 0.0099 只差 2%，但比 §5 外推的 0.0052
> **大了 87%** —— 这就是 §7.5 那个 t 预测落空的直接来源。）

### 5.11 块 id 里 `t0` 的语义：**会话内起点，单位秒**（2026-09-18 16:4x，`scripts/g1_e4x_t0_semantics.py`）

#### 为什么值得单列一节

2026-09-18 的一次诊断里我把 `t0` 当成了**毫秒**，于是算出「同会话 12 块的时间跨度
中位数只有 1.6 秒」，进而怀疑「同会话的块几乎重合 ⇒ 有效样本量是 100 个会话而不是
1600 块 ⇒ 全项目的 SE 都被低估」，并为此跑了会话簇 bootstrap。

簇 bootstrap 给 **0.97×**（块级 0.009772 vs 会话簇 0.009447）⇒ 聚类假说被排除。
**但那个假说的前提本身是我读错的**：跨度中位数是 **1595 秒 = 26.6 分钟**，完全正常。
⇒ 把语义钉死，免得再有人（包括我）按错的单位推理。**一个错的单位会凭空造出一个
需要被证伪的假说，而且证伪它的成本（一次 14-run 的实验预算？）可能很高。**

#### 语义（三重证据）

1. **代码**：`ari_g1_eval4_ids.py:127` 里 `t = 0.0` 起步、`t += STRIDE`(5.0)，
   循环条件 `while t + CHUNK_S(10.0) <= tmax`，而 `tmax = t0a[-1]` 是**帧时间戳（秒）**；
   id 由 `f"{s8}_ch{ch}_t{int(t)}"` 拼成。
2. **建库**：`ari_g1_prep_subset.py:161` 用 `int(t0 * 16000)` 切片 ⇒ 16 kHz 下 `t0` 是秒。
3. **结构**：`200 个 (session, ch) 键 × 每个正好 8 块 = 1600`（也等于 100 会话 × 16 块）。

#### 波形实测（4 条判据，全过）

| 判据 | 预期 | 实测 |
|---|---|---|
| **自检**：块与自身 lag=0 的 NCC | 必须 = 1 | **1.000000** ✅ |
| **1**：同键 Δt<10s 的对（29 对），在滞后 `−Δt×16000` 上 | 高（共享音频） | 中位数 **0.970** ✅ |
| **2**（负对照）：Δt>100s 的对，在 \|lag\|≤2s 内扫遍所有对齐 | 都该低 | 最大 **0.057** ✅ |
| **3**（反证）：把 Δt 按**毫秒**读得到的滞后 | 若毫秒说成立就该高 | **−0.021** ⇒ 毫秒假说**被证伪** ✅ |

#### 🔴 判据 2 的第一版写错了，值得记一笔

第一版问的是「Δt=105s 的对**在预测滞后 `−105×16000` 上**的 NCC 是多少」，
打出 `nan` 并判 🔴。**那是判据落进了没定义的区间**：105s 的滞后 = 1,680,000 采样，
而块本身只有 160,000 采样 ⇒ `ncc()` 的切片为空 ⇒ 返回 `nan` ⇒
`abs(nan) < 0.3` 是 **False** ⇒ 静默掉进「不通过」分支。

- 105s 间隔的两块**结构上就不可能有重合**，让它们"在预测滞后上取相关"本身就是无意义的提问；
- **NaN 在阈值比较里静默变成 False**，于是「没定义」被读成「没通过」——
  这正是 memory `threshold-must-match-null-model` 里「判据要把值域铺满」那一支。
- 改成它本该问的问题（在数据能支撑的滞后范围里扫遍所有对齐，且把 `重合=0` 断言出来），
  值域铺满，不留 NaN。

#### 📌 结论

> `t0` = **该块在会话内的起点，单位秒**，id 里取整。
> 块长 10s、候选池步进 5s ⇒ **候选池内**相邻窗口共享 50% 音频；
> 但**被选中的块**在会话内几乎均匀散开（同键相邻间隔中位 **170s**），
> 只有 **29/1400** 对真的重叠 ⇒ **块间音频重合不是常态**，
> 「1600 块其实只有 ~100 个独立样本」这个担忧**不成立**。

### 5.12 会话级分解：**「效应集中在哪」这个问题本身没有分辨率**（2026-09-18，`scripts/g1_e4x_decomp.py`）

#### 动机：先拆掉一个假发现

一次内联探针打出「100 个会话里 **65 个 ΔF1 ≡ 0**」，看着像「效应集中在少数会话」。
**那不是发现，是定义**：`f1_of` 在 `tp=fp=n_gt=0` 时 `p=r=0` ⇒ 直接 `return 0.0`，
两臂都一样 ⇒ **任何不含真值事件的会话 ΔF1 恒等于 0**。

对账（精确）：`无事件 54 + 恰好持平 11 = 65`，`正 25 / 负 10`。
⇒ **探针的每个数字都是对的，错的是对它的读法**：那 65 里 **54 个是构造性的**，
只有 11 个是「两臂在这 16 块上恰好完全一样」的巧合。把「定义」读成「集中」，
等于把一句信息量为零的话写成了机制。

#### 主结果：分辨率在**事件数**上，不在会话上

| 事实 | 数 |
|---|---|
| 真值事件总数 | **65** |
| 落在 | 64 个块 / **46 个会话** |
| 每个有事件的会话有几个事件 | **1~4 个**（多数是 1） |
| 逐会话 ΔF1（46 个） | 均值 +0.0393，SD 0.1085，**正号 25/46** |

> 46 个会话里 25 正 21 负 —— 一次硬币投掷。**F1 的分子是小整数（1~4），
> 最小非零变化都是 0.5 量级，逐会话排序纯属噪声排序。**

#### 计数分解：连「效应挂在 tp 还是 fp 上」也定不下来

表面上有个很干净的故事：own10 的 `tp` 27.0 > mixnorm 22.0，`fp` 532.3 < 550.0
—— **召回更好、假阳性更少，两边都对**。但把**逐种子**摆出来：

| Δtp | +5.0 | 2.9 | 2.9 | **4.1** | +12 +0 +16 +7 +5 −7 +2 |
| Δfp | −17.7 | **72.1** | 19.9 | **74.8** | **+200 −157 +68 +27 −25 −365 +128** |

⇒ **两个都「与 0 无异」**（|Δtp| 5.0 < 2×4.1；|Δfp| 17.7 < 2×74.8）。
fp 计数跨种子 SD ≈ 190（!），而臂间差只有个位数 ——
**计数这个量没有 F1 那种「两臂配对比值」的自平均**，单次 run 的摆幅远大于臂间差。

#### 🔴 两个前沿文件的判决相反，而它们只差 400 个块

`g1_e4_frontier.txt` 与 `g1_e4x_frontier.txt` 用同一个脚本算「块数 → 天花板 t」，
输入是两个**嵌套**的评估集（`e4 ⊂ e4x`）：

| | ΔF1 | SE_chunk | 分母 `(ΔF1/2)²−SE_chunk²` | 天花板 t | 判决 |
|---|---|---|---|---|---|
| **e4**（1200 块） | +0.0210 | 0.009725 | **+1.57e-05** | **2.155** | 可及：需 1.36× 块 + 4.9 种子 |
| **e4x**（1600 块） | +0.0163 | 0.009772 | **−2.91e-05** | **1.667** | 🔴 **死路：无穷多种子也够不到 2** |

> **同一批 adapters、同一批种子、同一个脚本，只因为评估集多了 400 块，
> 「这个问题有没有答案」就反过来了。**

#### 为什么会翻：分母是两个**几乎相等的大数之差**

```
e4   (ΔF1/2)² = 1.1025e-04    SE_chunk² = 9.4576e-05   →  分母 +1.57e-05  (首项的 +14.2%)
e4x  (ΔF1/2)² = 6.6422e-05    SE_chunk² = 9.5492e-05   →  分母 −2.91e-05  (首项的 −43.8%)
```

两个平方项**只差 14%**，而分母就是它们的差 ⇒ **分母继承的是两个大数各自的误差，
不是差本身的精度**。而 ΔF1 在**平方**里面：

```
ΔF1:  +0.0210 → +0.0163    (−22.4%, 线性)
平方:  (ΔF1/2)²            (−39.8%, 放大了 1.8 倍)
```

⇒ 一个 22% 的线性漂移（§5.10 已证明这种量级的池间漂移**确实存在**），
在平方项里变成 40%，直接把一个**只有 +14% 余量**的差推过零。

> 🔑 **可推广的那一句**：**当判据写成「两个大数之差」时（功效反解、天花板 t、
> 余量/所需样本量），它的符号继承的是两个大数各自的噪声 —— 这类判决不能跨数据集引用。**
> 本项目的判据恰好长这样：`n ∝ SD² / ((ΔF1/2)² − SE_chunk²)`。
> 分母过零时 `n` 从「12.7 个种子」跳到「无穷大」，中间**没有过渡** ——
> 这不是「结论不稳」，是**这个问题在这个数据集上被问坏了**。
> 与 memory `stochastic-estimate-as-threshold-needs-mc` 同族（判据线是随机量），
> 但形态更狠：那条是**线在漂**，这条是**线漂过了导致的符号翻转**，
> 而翻转的那一版会被读成「数学上不可能」（"死路，不是不稳"）。

#### 📉 那么 e4x 的「死路」判决值多少

**只值它自己那个数据集。** 定量地说，e4x 要「不死」需要：

```
天花板 t > 2  ⟺  SE_chunk < ΔF1/2 = 0.00815   (现在 0.009772, 差 19.9%)
按池内实测指数 −0.508 反解 ⇒ 最小可行块数 k ≈ 2287  (现 1600 的 1.43×)
且 k → k_min 时分母 → 0 ⇒ 所需种子数 → ∞
```

⇒ **「死路」不是一个关于实验设计的结论，是一个关于 ΔF1 = +0.0163 这个点估计的结论。**
把点估计换成 e4 的 +0.0210，同一条路立刻变成「1.36× 块 + 5 个种子」。
**而点估计该是哪个，恰恰是本研究没有解决的问题。**

#### 所以下一步做什么

**⛔ 不建议：继续加块。** 理由不是 e4x 那个死路判决（见上，它不可靠），
而是**更朴素的一条**：§5.10 已实测加块**降不动 `SE_chunk`**（池水平 ×1.16 抵消了尺寸收益），
而所有功效账的分子都写着 `ΔF1` —— 一个在嵌套集之间漂了 22% 的量。
**在点估计的漂移（±22%）大于它到判据线的距离（−16%）时，加块只是把同一个不确定性买得更精确。**

**✅ 建议：把 `ΔF1` 的**池间分布**量出来 —— 这是唯一还没做、且 0 训练的事。**

两个前沿文件都明写了同一个缺口：

> ⚠️ 但外推倍数见上表: 只在**这批块的总体**内成立, **不含「换一批块 ΔF1 会漂多少」**。

§5.10 用 **n = 1 批**（新增的那 400 块）估出漂移 −0.0198，**t = −0.66 不显著** ——
即「漂移与效应同量级」这句话**目前只有 1 个观测点在撑**。补法：

1. **从自然流行率池里再独立抽 2~3 批**（每批 400~800 块），
   用**已有的 7 个 adapter** 评估，**0 训练**。e4b 的先例表明这在现有算力内可行。
2. 直接算出 **ΔF1 的池间 SD**（不是 bootstrap 的 `SE_chunk` —— bootstrap 只重抽**已有**的块，
   **结构上看不见池子之外的变异**，这与 §5.10 的「池水平会动」是同一件事）。
3. **预登记判读**（先写死，再跑）：
   - 池间 SD ≳ 0.020 ⇒ **效应落在池间噪声里，这个端点在任何可负担的规模下都判不出来**

   - 池间 SD ≪ 0.010 ⇒ e4x 的 +0.0163「线下」是站得住的答案，§5.10 的翻转是**那一批块**的偶然。
