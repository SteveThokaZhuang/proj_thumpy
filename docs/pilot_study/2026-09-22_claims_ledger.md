## 一、✅ 已证实（可以当基石用）

### A. 工程管线 —— 这一层最硬，没被推翻过

**1. 全流程是真的通的。**
数据构建 → LoRA 训练 → 生成式评估 → 事件级 F1，两臂各 7 个种子全部跑完，
没有哪一环是纸上推的。
📎 syllabus §2.1

**2. 评估集里有过一个真 bug，已经修了。**
旧评估集里相当一部分真值事件**横跨 10 秒块的边界** —— 这种块的答案是「不可答」的，
模型在它们上面「永远做不对」不是模型的毛病，是题目本身没答案。
修掉（`require_inside`）之后的版本才是现在对外报的口径（后缀 `_filt`）。
📎 syllabus §2.2 ｜ memory `windowed-eval-check-gt-straddles-boundary`

**3. 决定模型「报还是不报」的那个量，找到了。**
是 `margin_max`（数字起始那一类 token 与非起始类的 logit 之差），
它和模型实际行为的吻合度约 97%。
更早用的 `margin_lse` 只有约 68%，因为数字类横跨 28 个 token、`no` 只有 1 个，
按类求和会系统性偏。**这个坑已经填了，别再用 `margin_lse`。**
📎 syllabus §2.3

**4. 全项目的 loss 曲线是假的 —— 但训练没坏。**
纯文本回复上 `speech_loss` 是 NaN，被 logging 的过滤器吞掉，于是记成了 0.0。
23 个 run 无一例外。
⇒ **不要再用 loss 曲线判断训练好坏**，那上面没有信息。
📎 syllabus §4 ｜ memory `loss-logging-nan-artifact`

**5. 块 id 里的 `t0` 是「会话内起点秒数」。**
不是全局时间、不是块序号。四条判据全过。
📎 `2026-09-17_k4_eval_set.md` §5.11

### C. G1 消融 —— 翻车之后还剩下什么

**10. 平均而言，own10 比 mixnorm 好一点点。**
方向在 7 个种子里一致；逐个会话做留一（去掉任一个会话重算），
一百次里**没有一次翻号** ⇒ 这个效应是**弥散**的，不是三五个会话或种子撑起来的。
⚠️ 但**幅度很小**：判据「均值 > 2×标准误」虽然仍满足，余量只剩 1.43 倍。
📎 `2026-09-18_pool_sd.md` §3.2 / §3.4

**11. mixnorm 的毛病不是「不稳」，是「每个 run 把边界画在了不同的地方」。**
各个 run 的**平均 margin** 散得很开（是 own10 的好几倍）。
这条经得起检验：显著、留一稳、在自然流行率集上复现、而且**与评估集标签无关**
（所以它不吃流行率那个伪影）。
👉 **这是 G1 那场翻车之后唯一幸存的核心结论。**
📎 syllabus §5.1

**12. 边界画在哪，几乎直接决定 mixnorm 的分数。**
mixnorm 上「各 run 平均 margin」与「各 run F1」的相关高到接近恒等式；
own10 上只有中等相关。
⇒ mixnorm 的 F1 基本上就是「阈值画在哪」的另一种写法。
📎 syllabus §5.2

**13. 驱动边界离散的是「run 级随机性」，不是初值。**
定住随机种子、只换数据顺序，离散度一样大。
（所以措辞要用「各 run」而不是「各种子」。）
📎 syllabus §5.1 的更正框 + §7.4f

**14. Q3 的答案：LoRA 初值不是原因，数据顺序是。**
`Var(init)` 检不出差异，抖动由 shuffle 主导。
📎 `2026-09-17_q3_q4.md` §4.5

### D. 抽样与设计 —— 本轮最硬的方法论产出

**15. 四个评估集**不是**四次独立抽取，是**同一次**抽取的连续切片。**
e4 / e4b / e4x / e4c 来自同一次固定 shuffle seed 的轮转抽样，
靠「累积排除」一段段切出来的 ⇒ 它们互相重叠、包含、前后相接。
👉 **推论：以前记的「批间漂移」，其实是「又多抽了几轮」的轮次效应，不是抽样漂移。**
📎 `2026-09-18_pool_sd.md` §2.5 ｜ memory `independent-batches-may-be-one-draw`

**16. 池与池之间的波动量级，量出来了。**
把各批自己的 ΔF1 去比对照零模型，比值落在「bootstrap 诚实」那一档（不拒绝原假设）。
⚠️ 但置信区间上界仍越过判据线 ⇒ 只能说「**没有证据说它不诚实**」，
不能说「已经证明它诚实」。
📎 `2026-09-18_pool_sd.md` §2.1（12 批）/ §2.6（16 批）｜ `g1_e4c_pool_sd.json`、`g1_e4c_pool_sd_ext.json`

**17. 历史上的块级标准误一直偏保守（略高估）。**
评估集是按「会话 × 声道」**分层**抽的，而历史上算标准误用的是**简单随机重抽**。
分层零模型比它低 7～11%（三个集一致）⇒ 过去的跨批波动被略微高估了。
📎 `2026-09-18_pool_sd.md` §1.3

**18. 「再加块」这条路已经走到头了。**
把「会话」这一项方差算进来之后，现有的块数**已经越过**「加块还能降标准误」的交叉点。
从这一百个会话里再加块，买到的改善可以忽略。
📎 `2026-09-18_pool_sd.md` §3.3 ｜ `g1_e4c_session_decomp.json`

**19. 〔新，2026-09-22〕帧轨迹可以省掉 —— 那笔 GPU 开销是白花的。**
整条评估链上，帧轨迹**只贡献一个标量**：每个会话音频的「末尾时刻」，
而块网格完全由它决定。它供的另一个东西（帧数够不够密的闸门）实测**一次都没拦过**
（八万多个网格位置里 0 个）。至于轨迹算出的另外两路特征，
评估路径**从头到尾没读过**。
代价：换成 mp3 时长之后，约六分之一的声道会**少一个末块**（多出来的那个本来就
越过了音频末尾）。所以这是**构造口径的一处改动**，要写明，不是「同一构造」。
收益：方案 C 的开销**砍掉约一半**。
📎 `2026-09-18_pool_sd.md` §5.1 ｜ `g1_trace_vs_mp3.json`

**20. 〔新，2026-09-22〕🔴 换会话时，评估集的「稠密度」会翻倍 —— 而这是被吃出来的。**
新的一百个会话本身和老的一百个**没有差别**（事件密度打了误差棒，与 0 无异）。
但 **e4c 实际抽样的那个候选池只有 ~3.9% 的块含事件，新池有 ~8.0%**，差一倍。
原因不是会话不同，而是：**老池子早就被前面的集子吃过一遍了** ——
训练集和那个 100% 正例的评估集把「有事件」的块几乎全挖走了（它们自己密度 70% 和 102%），
剩下的自然稀。
👉⇒ **在同一批会话上「复现」和在全新会话上「复现」，流行率不一样，
而流行率正是当初翻转结论的那个变量。** 预登记必须写两个读数。
📎 `2026-09-18_pool_sd.md` §5.3 ｜ `g1_newpool_candidates.json`

## 四、🧠 贯穿全程的方法论教训（本项目最可迁移的产出）

> 这一节是**踩过的坑**，不是结论。写下来是因为它们在同一个项目里
> 用**不同的端点**反复发作 —— 换一个统计量就重犯一次。

1. **一个检验把哪个因子钉死了，它就看不见那个因子。**
   本项目在三个不同端点上犯了**同一个**错：钉死块、钉死种子、钉死会话。
   每次的后果都一样 —— 得到一个**看起来更显著**的结论。
   👉 动手前先问：「这个抽法里，哪些因子每次重抽取值不变？」

2. **「三个独立检验都支持」不等于稳。**
   如果这三个检验的零模型**都钉死了同一个因子**，它们支持的是**同一个盲区**。
   要看的是它们**各自钉死了什么**。

3. **计数类的量没有自平均。**
   F1 是两臂配对比值，噪声会互相对消；「多报了 N 个」不会。
   单次 run 的摆幅可以比臂间差大一个量级。

4. **凡是「按种子存的文件」，第一个永远是第一个种子。**
   默认读到的是同一个 run，不是「两臂的差别」。
   在把任何差值写成结论之前，先把它按种子列出来。

5. **阈值必须先对零模型，而且判据要把值域铺满。**
   本项目一晚上栽了三次：太严出假警报、太松出假发现、判据只比典型值大一点点。
   还有一条：**判据没有定义的区间，值掉进去会被静默判成 False。**

6. **小样本会把噪声包装成发现。** 已知的形态：
   点太少出伪异常、跑批没跑完就下结论、差值没配误差棒、
   相关系数靠单点撑着（留一就散）。

7. **开跑前先做功效分析。**
   有一次跑完 7 对之后才发现「最小可检测效应」比要测的效应还大 —— 白跑。

8. **扩评估集买的是诊断，不是功效。**（见「已证伪」第 13 条）

9. **结论里的数字别写死。**
   写死的常数会活过口径变更，还会借走旁边「现算量」的可信度。
   同族：**先填表后核数** —— 从比值反推编出数来，真值不一样。
   🔁 **第三例〔2026-09-23〕：口径从 28 对话扩到 54 之后，旧数字在 4 个地方活着。**
   F5 把 Fisher 抽样从 50 提到 100、有转写者 28→54，
   `f5_fisher.md` 的 §2 表换了新数（0.844 / 0.624 / 0.380），
   但 **§1 的方法节、§3 的裁决行文、`2026-08-26_fd_flywheel_plan.md` 的 F5 行、
   `2026-08-28_story_report.md` 的 Act 2 表** 全部仍挂着初版的
   **0.839 / 0.616 / 0.33 / "28 段"**（连带"WER 恶化 7 倍"也该是 8 倍）。
   🔑 **可迁移的那一步**：入口文档的缺口表把这件事记成「§3/§4 两处」——
   **而实际是 4 处**。⇒ **「有几处要改」这个数本身就是个会漏的数**：
   排查受影响范围时**不许信任何清单（包括自己刚写的）**，
   要 `grep` 那个具体数字本身。
   👉 而**判据没有变**：三条裁决的方向一条没动 —— **换数不换结论，但必须换数。**

10. **配对设计的地板在交互项。**
    同种子配对约掉的是种子的**主效应**，约不掉「种子 × 批」的**交互**，
    而那一项往往最大。加批缩不到种子那一路。

11. **改完代码重启，要确认活下来的是新进程。**
    留着一个「还在正常跑」的旧进程 = 修复白做，而且被跳过的步骤会静默缺失。

12. **引用现成产物之前，先核它的粒度、覆盖面和正例率。**
    差点拿一份「帧级二十万观测」的产物去开一笔 GPU 开销 ——
    细看是逐块几百个值、和目标集交集为 0、而且恰好看不见它被引来「看见」的那部分。

13. **报方差之前，先报正例率。**
    一个 100% 正例的集合测不出判别力，只能测操作点。

14. **join 键命中率 100% 与实体同一性 0% 可以同时成立。**
    `example_id` 50/50 全命中，逐 turn 内容却 0/50 相同 —— 同一 id 装的是两段不同对话。

22. 🔴 **「两条独立读数」可以是代数上同一个量 —— 于是预登记的预测注定失败（或注定通过）。**
    〔新，2026-09-23，§5.2c 预登记〕写「数字拼接」的 base rate 时定了三条主读数，第一条是

    ```python
    both     = (L != 0) & (R != 0)      # 双方同时出声
    one_zero = (~both).mean()           # 「主读数 1」：除重叠外总有一侧是数字零
    overlap  = both.mean()              # 「主读数 2」
    ```

    **`one_zero ≡ 1 − overlap`。** 于是 P1(`one_zero ≥ 99%`) ⟺ P2(`overlap ≤ 1%`)，
    两条号称独立的读数**不可能一真一假**；而 P2 预测的中位重叠是百分之几
    ⇒ **P1 在被写死的那一刻就注定失败**。冒烟一跑果然报"未达 2.4%"。

    ⇒ 与老账 `permutation-test-covers-one-variance-source`（「三个独立检验支持
    可能只是同一个盲区」）**同族但形态是新的**：那条讲几个检验**共享一个盲区**
    （所以一致不构成证据）；本条讲两个读数**根本就是同一个量**
    （所以一致是恒真的、分歧是不可能的）—— 连"独立"的资格都没有。

    ⇒ **预登记特有的纪律**：写完预测后，**逐条验算它们之间有没有代数关系**
    （这里 `a + b = 1` 一眼可见，但当时没验）。同族：恒真自检、写死常数借走现算量的可信度。

    ⇒ 有意思的是**逮住它的是冒烟，不是全量**：小样本先跑一次的价值不只是省时间，
    它会把"注定失败"的预测在花大成本之前顶出来。

    ⇒ 更正后的 P1' 要**另找与被检量无关的量**：问的是"静止声道是不是精确的零"
    （有没有混响/串音/本底噪声），就量**每声道精确零的样本占比**、
    **有声样本中 < −60 dBFS 的比例**、**最小非零幅度 vs 量化步长** —— 这三条都不含 `overlap`。
    更正**写于看到 165 条冒烟之后**，所以在文档里**标明是事后更正、不是预登记**。

23. 🔴 **打平的 `argmax` 会把「无法判定」读成一个**具体的类别**。**

27. 🔴 **「正好一半」不是一个数，是一个恒真事实的投影。**
    〔新，2026-09-23，HumDial 勘察〕同一个下午在**同一批数据**上，
    我的三版探针各自给出一个**看起来像结果**的数，三个全是假的 —— 形态不同、机理同族：

    | # | 症状（我打印出来的） | 真相 | 机理 |
    |---|---|---|---|
    | ① | 「逐字相同 **1635/3272 = 正好 50.0%**」 | 语料一半中文，**中文那半全被规范化没了** | `NORM = re.compile(r"[^a-z0-9]+")` 把**汉字整个删掉** ⇒ 所有 `cn_*` 对规范化成 `""` ⇒ 两两"相等" |
    | ② | 「逐样本 maxΔ 0.98、逐帧能量相关 0.43 ⇒ **clean 是另一路音频**」 | clean **按定义**只保留第一轮，第二轮静音 | 我拿**全部** `speech_segments` 造掩码 —— 掩码把"按定义静音"的那段也圈成了"用户区间" |
    | ③ | 「用户区间内逐样本完全相等 **0 个** / 不相等 **0 个**」 | **样本被筛光了**，一个都没比 | `len(a1) != len(a2): continue`，而两者时长比是 1.0004（差 ~12 ms） |

    三条各自的教训：

    - **①** ⇒ 规范化函数要**先自测**：喂两个**不该相等**的字符串（这里是两句无关中文），
      它们必须不相等。`re.compile(r"[^a-z0-9]+")` 在纯英料上完全正确，
      **换一半中文就变成恒真检查** —— §四里反复出现的那条**"恒真自检"**母题
      （第 16/19/22/23 条都以"同族"提到过）换个马甲又来了。
      👉 **整齐得可疑的数要先怀疑仪器**：「正好 50.0%」我当时觉得"像配对错位"，
      **方向对了、层级错了** —— 不是配对错，是**比较本身**退化了。
      正确的规范化：`"".join(c for c in s.lower() if c.isalnum())`（`str.isalnum()` 对 CJK 返回 True）。
      🔴 **修完之后两个量的命运完全不同，这才是关键**：同一个 bug 污染了两次测量，
      修好后一个**塌到 8/3272 = 0.24%**（`clean_X_timestamp` vs `X_timestamp`），
      另一个**基本没动、仍是 2111/4172 = 50.6%**（`speech_segments` vs `chunks`）。
      后者是**真发现**（参考文本 ↔ ASR 假设），它落在"一半"附近是**内容使然**，
      不是 bug 的残留。⇒ **「数变了没」不能用来判断修没修对** ——
      要看**这个比较实际在比什么**（两个坏数一个塌一个不塌，若只看"变没变"会得出相反结论）。
    - **②** ⇒ **掩码必须只圈"因数据而变"的区间**。clean 在后几轮静音是**定义**，
      不是观测 —— 用它在那些区间上量出的差异**是我的仪器造的**
      （`[[threshold-must-match-null-model]]` 第五面：定义域里按定义恒定的那一段会被读成发现）。
      🔑 **破除成本是零**：`humdial_group_dump.py` 把一条数据**全文摊开**，
      一眼就看到 `clean_X_timestamp` 只有第一轮 —— **统计量解释不了的时候，去看那条数据本身。**
    - **③** ⇒ **分母要和分子一起打印**。三个数里最危险的是 ③：它**不是错的数，是空的数**，
      而空表长得就像"结果是 0"。同时打印分母才让它现形
      （§四.25 孪生面"过滤器会制造缺口"的同一次出差）。

    ⇒ 合并成一条纪律：**跑完探针先问"这个数会不会是恒真的、被仪器造的、或者压根没算成"**，
    三问各配一个动作 —— **自测规范化函数 / 摊开一条原始数据 / 打印分母**。
    ⚠️ 三个数里 ① 最危险：**它错了以后给出的数最像真结果**
    （1635/3272 修好后是 8/3272，**可它的兄弟量修好后仍是 50.6% 的真值** ——
    两个量长得一样、一个全假一个全真，**肉眼分不出**）。
    ⇒ **判据不能是"数看起来合不合理"，只能是"这个比较按定义在比什么"。**

    ｜ `[[tiebreak-default-read-as-evidence]]` ｜ `[[hardcoded-conclusions-escape-reproduction]]`

28. 🔴 **分档的判语比数字更响 —— 你在脚本里随手写的那个阈值，替你下了结论。**〔2026-09-23〕
    拆 HumDial 那 104 万未覆盖帧时，我在脚本里写了个三分支：
    `if hole > 3*edge … elif edge > 3*hole … else "两者量级相当"`。
    实测 **洞 68.2% ／ 边界缩 31.8%**（比值 2.15）⇒ **没够到 3×** ⇒
    脚本原样打印「**两者量级相当，不许二选一**」——
    而 68:32 明明是**洞占多数**。**落到正文里的是我手算的那两个百分比，
    不是脚本那句判语**（prereg §9 自陈错误 #2）。
    👉 三条：
    - **判语要和数字一起打印**，别让分支替你选一个形容词；
    - **分档阈值也是阈值** —— 同样要先对零模型（第 5 条），
      而这里那个 `3×` 是**拍脑袋定的**，于是它静默决定了三句话里打印哪一句；
    - 🔴 **日志里会被引用走的恰恰是那句判语**，不是旁边那串数字
      ⇒ **一句错判语的杀伤力大于一个错数字**。
    ⚠️ **同一次脚本还犯了第二件**：M4 按轮次时长分箱，**每个箱都打印 FP ≡ 0** ——
    那是**构造使然的恒零**（分箱只在 R 轮次区间内取帧，区间内 R 按定义活动），
    于是那一列「F1」其实是**只有 recall 的假 F1**（第 5 条「定义域里按定义恒定」那一面的复现）。
    处置按第 26 条办：**旧读数原样留在日志里不动**，另写诚实版。
    👉 两件的共同根：**预登记纪律只管住了预登记的那几个判据**；
    写代码时顺手加的辅助分支**不受它管，但读者照样会引用**。
