## 一、✅ 已证实（可以当基石用）

### A. 工程管线 —— 这一层最硬，没被推翻过

**1. 全流程是真的通的。**
数据构建 → LoRA 训练 → 生成式评估 → 事件级 F1，两臂各 7 个种子全部跑完，
没有哪一环是纸上推的。
📎 syllabus §2.1

**2. 评估集里有过一个真 bug，已经修了。**
旧评估集里相当一部分真值事件**横跨 10 秒块的边界** —— 这种块的答案是「不可答」的，
模型在它们上面「永远做不对」不是模型的毛病，是题目本身没答案。
修掉（`require_inside`）之后的版本才是现在对外报的口径（后缀 `_filt`）。
📎 syllabus §2.2 ｜ memory `windowed-eval-check-gt-straddles-boundary`

**3. 决定模型「报还是不报」的那个量，找到了。**
是 `margin_max`（数字起始那一类 token 与非起始类的 logit 之差），
它和模型实际行为的吻合度约 97%。
更早用的 `margin_lse` 只有约 68%，因为数字类横跨 28 个 token、`no` 只有 1 个，
按类求和会系统性偏。**这个坑已经填了，别再用 `margin_lse`。**
📎 syllabus §2.3

**4. 全项目的 loss 曲线是假的 —— 但训练没坏。**
纯文本回复上 `speech_loss` 是 NaN，被 logging 的过滤器吞掉，于是记成了 0.0。
23 个 run 无一例外。
⇒ **不要再用 loss 曲线判断训练好坏**，那上面没有信息。
📎 syllabus §4 ｜ memory `loss-logging-nan-artifact`

**5. 块 id 里的 `t0` 是「会话内起点秒数」。**
不是全局时间、不是块序号。四条判据全过。
📎 `2026-09-17_k4_eval_set.md` §5.11

**这 1,656 个每一个都有音频**（可用率 100%），不存在「目录在、文件不在」的坑。

不是「重新标一遍数据」—— 这件事以前一直以为很贵。

⇒ **所以换一批会话就是真正的样本外**，不是「换个取样口再抽一次」。
本次还实测确认：**新一批会话的事件密度和老一批没有差别**（打了误差棒，与 0 无异）。

### C. G1 消融 —— 翻车之后还剩下什么

**10. 平均而言，own10 比 mixnorm 好一点点。**
方向在 7 个种子里一致；逐个会话做留一（去掉任一个会话重算），
一百次里**没有一次翻号** ⇒ 这个效应是**弥散**的，不是三五个会话或种子撑起来的。
⚠️ 但**幅度很小**：判据「均值 > 2×标准误」虽然仍满足，余量只剩 1.43 倍。
📎 `2026-09-18_pool_sd.md` §3.2 / §3.4

**11. mixnorm 的毛病不是「不稳」，是「每个 run 把边界画在了不同的地方」。**
各个 run 的**平均 margin** 散得很开（是 own10 的好几倍）。
这条经得起检验：显著、留一稳、在自然流行率集上复现、而且**与评估集标签无关**
（所以它不吃流行率那个伪影）。
👉 **这是 G1 那场翻车之后唯一幸存的核心结论。**
📎 syllabus §5.1

**12. 边界画在哪，几乎直接决定 mixnorm 的分数。**
mixnorm 上「各 run 平均 margin」与「各 run F1」的相关高到接近恒等式；
own10 上只有中等相关。
⇒ mixnorm 的 F1 基本上就是「阈值画在哪」的另一种写法。
📎 syllabus §5.2

**13. 驱动边界离散的是「run 级随机性」，不是初值。**
定住随机种子、只换数据顺序，离散度一样大。
（所以措辞要用「各 run」而不是「各种子」。）
📎 syllabus §5.1 的更正框 + §7.4f

**14. Q3 的答案：LoRA 初值不是原因，数据顺序是。**
`Var(init)` 检不出差异，抖动由 shuffle 主导。
📎 `2026-09-17_q3_q4.md` §4.5

### D. 抽样与设计 —— 本轮最硬的方法论产出

**15. 四个评估集**不是**四次独立抽取，是**同一次**抽取的连续切片。**
e4 / e4b / e4x / e4c 来自同一次固定 shuffle seed 的轮转抽样，
靠「累积排除」一段段切出来的 ⇒ 它们互相重叠、包含、前后相接。
👉 **推论：以前记的「批间漂移」，其实是「又多抽了几轮」的轮次效应，不是抽样漂移。**
📎 `2026-09-18_pool_sd.md` §2.5 ｜ memory `independent-batches-may-be-one-draw`

**16. 池与池之间的波动量级，量出来了。**
把各批自己的 ΔF1 去比对照零模型，比值落在「bootstrap 诚实」那一档（不拒绝原假设）。
⚠️ 但置信区间上界仍越过判据线 ⇒ 只能说「**没有证据说它不诚实**」，
不能说「已经证明它诚实」。
📎 `2026-09-18_pool_sd.md` §2.1（12 批）/ §2.6（16 批）｜ `g1_e4c_pool_sd.json`、`g1_e4c_pool_sd_ext.json`

**17. 历史上的块级标准误一直偏保守（略高估）。**
评估集是按「会话 × 声道」**分层**抽的，而历史上算标准误用的是**简单随机重抽**。
分层零模型比它低 7～11%（三个集一致）⇒ 过去的跨批波动被略微高估了。
📎 `2026-09-18_pool_sd.md` §1.3

**18. 「再加块」这条路已经走到头了。**
把「会话」这一项方差算进来之后，现有的块数**已经越过**「加块还能降标准误」的交叉点。
从这一百个会话里再加块，买到的改善可以忽略。
📎 `2026-09-18_pool_sd.md` §3.3 ｜ `g1_e4c_session_decomp.json`

**19. 〔新，2026-09-22〕帧轨迹可以省掉 —— 那笔 GPU 开销是白花的。**
整条评估链上，帧轨迹**只贡献一个标量**：每个会话音频的「末尾时刻」，
而块网格完全由它决定。它供的另一个东西（帧数够不够密的闸门）实测**一次都没拦过**
（八万多个网格位置里 0 个）。至于轨迹算出的另外两路特征，
评估路径**从头到尾没读过**。
代价：换成 mp3 时长之后，约六分之一的声道会**少一个末块**（多出来的那个本来就
越过了音频末尾）。所以这是**构造口径的一处改动**，要写明，不是「同一构造」。
收益：方案 C 的开销**砍掉约一半**。
📎 `2026-09-18_pool_sd.md` §5.1 ｜ `g1_trace_vs_mp3.json`

**20. 〔新，2026-09-22〕🔴 换会话时，评估集的「稠密度」会翻倍 —— 而这是被吃出来的。**
新的一百个会话本身和老的一百个**没有差别**（事件密度打了误差棒，与 0 无异）。
但 **e4c 实际抽样的那个候选池只有 ~3.9% 的块含事件，新池有 ~8.0%**，差一倍。
原因不是会话不同，而是：**老池子早就被前面的集子吃过一遍了** ——
训练集和那个 100% 正例的评估集把「有事件」的块几乎全挖走了（它们自己密度 70% 和 102%），
剩下的自然稀。
👉⇒ **在同一批会话上「复现」和在全新会话上「复现」，流行率不一样，
而流行率正是当初翻转结论的那个变量。** 预登记必须写两个读数。
📎 `2026-09-18_pool_sd.md` §5.3 ｜ `g1_newpool_candidates.json`

## 二、🔴 已证伪（不要再引用）

**1. 「mixnorm 不稳定，方差是 own10 的十几倍」—— 本项目最大的一次翻车。**
那是**评估集流行率**造成的伪影：那套评估集里**每一块都有正例、一个负例都没有**，
于是「多报」只增加命中、几乎不增加误报 —— 谁把阈值画得野，谁的分数就乱跳。
换到自然流行率的集上，**方差排序直接反转**（mixnorm 反而更稳）。
📎 syllabus §3.2–3.4 ｜ memory `prevalence-flips-variance-conclusions`

**2. 「ΔF1 ≈ +0.034，弱显著（p≈0.05）」—— 站不住。**
那个置换检验只让**种子**随机、把块当成固定的；而「能不能推广到别的块」
恰恰是要问的问题。把块抽样算进去，t 从 2.9 掉到 1.5。
📎 syllabus §7.2 ｜ memory `permutation-test-covers-one-variance-source`

**3. 「加块比加种子划算」—— 实测证伪。**
真去加了块（加 400 块），块级标准误**没有**按预测降下来。
📎 `2026-09-17_k4_eval_set.md` §5.10

**4. 「加块有硬地板、天花板 t≈6.8」—— 被「会话」这一项推翻。**
真实地板比它高一大截，真实天花板只有约 4.0。
⚠️ **那个 6.8 只有在「会话和种子都取无穷多」时才够得到，它不是「加块」的上限。**

📎 `2026-09-18_pool_sd.md` §2.5

**6. 「mixnorm 把决策整体压到了阈值附近」—— 原假设证伪。**
种子**内部**看，mixnorm 反而更果断；真正炸掉的是种子**之间**边界位置不一致。

**7. 「某些种子欠拟合 / 训练没到位」—— 排除。**

那些会话里**根本没有真值事件**，F1 恒等于 0 是算术必然。
（后来逐会话留一证实效应其实是弥散的。）

同一个判决，在两个只差 400 块的评估集上，一个说「可及」、一个说「死路」。

## 四、🧠 贯穿全程的方法论教训（本项目最可迁移的产出）

> 这一节是**踩过的坑**，不是结论。写下来是因为它们在同一个项目里
> 用**不同的端点**反复发作 —— 换一个统计量就重犯一次。

1. **一个检验把哪个因子钉死了，它就看不见那个因子。**
   本项目在三个不同端点上犯了**同一个**错：钉死块、钉死种子、钉死会话。
   每次的后果都一样 —— 得到一个**看起来更显著**的结论。
   👉 动手前先问：「这个抽法里，哪些因子每次重抽取值不变？」

2. **「三个独立检验都支持」不等于稳。**
   如果这三个检验的零模型**都钉死了同一个因子**，它们支持的是**同一个盲区**。
   要看的是它们**各自钉死了什么**。

3. **计数类的量没有自平均。**
   F1 是两臂配对比值，噪声会互相对消；「多报了 N 个」不会。
   单次 run 的摆幅可以比臂间差大一个量级。

4. **凡是「按种子存的文件」，第一个永远是第一个种子。**
   默认读到的是同一个 run，不是「两臂的差别」。
   在把任何差值写成结论之前，先把它按种子列出来。

5. **阈值必须先对零模型，而且判据要把值域铺满。**
   本项目一晚上栽了三次：太严出假警报、太松出假发现、判据只比典型值大一点点。
   还有一条：**判据没有定义的区间，值掉进去会被静默判成 False。**

6. **小样本会把噪声包装成发现。** 已知的形态：
   点太少出伪异常、跑批没跑完就下结论、差值没配误差棒、
   相关系数靠单点撑着（留一就散）。

7. **开跑前先做功效分析。**
   有一次跑完 7 对之后才发现「最小可检测效应」比要测的效应还大 —— 白跑。

8. **扩评估集买的是诊断，不是功效。**（见「已证伪」第 13 条）

9. **结论里的数字别写死。**
   写死的常数会活过口径变更，还会借走旁边「现算量」的可信度。
   同族：**先填表后核数** —— 从比值反推编出数来，真值不一样。

10. **配对设计的地板在交互项。**
    同种子配对约掉的是种子的**主效应**，约不掉「种子 × 批」的**交互**，
    而那一项往往最大。加批缩不到种子那一路。

11. **改完代码重启，要确认活下来的是新进程。**
    留着一个「还在正常跑」的旧进程 = 修复白做，而且被跳过的步骤会静默缺失。

12. **引用现成产物之前，先核它的粒度、覆盖面和正例率。**
    差点拿一份「帧级二十万观测」的产物去开一笔 GPU 开销 ——
    细看是逐块几百个值、和目标集交集为 0、而且恰好看不见它被引来「看见」的那部分。

13. **报方差之前，先报正例率。**
    一个 100% 正例的集合测不出判别力，只能测操作点。

14. **join 键命中率 100% 与实体同一性 0% 可以同时成立。**
    `example_id` 50/50 全命中，逐 turn 内容却 0/50 相同 —— 同一 id 装的是两段不同对话。
    只按索引交集"对齐"过一次，拿到的是**撞号**不是对齐（recon §3.1 留档）。

15. **置换检验必须保住数据的结构不变量**，否则会造出非法样本、把结论**方向弄反**。
    这次打乱的是「票数」而不是「伯努利试验」⇒ 把 m=5 槽的 3 票挪到 m=2 的槽上
    （"2 个人里 3 个人说是"）⇒ 零分布 1.40 > 观测 1.04。
    🔑 **照出它的是功效分析里 delta=0 那一行（size 校验）** ⇒
    **功效分析不只是「能不能检出效应」，也是装置自检。**

16. **不要为了让脚本通过而调阈值。**
    给「载入器是否与论文 Table 5 一致」拍了个 1% 门禁，结果拦下一个 1.21% 的真实差异。
    正确做法是把两件事拆开：**自己的正确性 = 硬断言**（用独立路径复核，会炸）；
    **与别人口径的差 = 报告项**（事实，不是门禁）。

17. **同一个一致性数据，两个统计量可以给出相反印象。**
    κ = 0.051 说"几乎没有一致"，AC1 = 0.369 说"中等偏下" —— 差别全在机遇一致度怎么定义。
    而且**逐场景的名次几乎完全倒过来**（TEA 与 INT 两端互换）。
    ⇒ **报 κ 前先报边际，两个都报，不要挑一个。**

18. 🔴 **「查了没找到」之前，先确认查的路径存在。**
    `grep -rn "模式" 相对路径 2>/dev/null` 在错目录下跑 ⇒ 报 "No such file"
    ⇒ **被 `2>/dev/null` 吞掉 ⇒ 空输出，和「没有匹配」长得一模一样**。
    差点据此写下「这个错数只此一处」。
    ⇒ **查「有没有」的脚本，必须先证明它看得见「有」**（拿一个已知存在的模式试一下）。
    同族：0 字节日志 ≠ 失败、恒真的自检、看不见的监控。

19. 🔴 **交稿前把每个数字回对落盘产物 —— 一核就逮到一个。**
    三分类表里 SOC 的 AC1 写成了 **0.4684**，那是**二值表**里同名的 SOC 行的值，
    真值 **0.3500**。**两张表都有叫「SOC」的行 ⇒ 抄串了肉眼看不出来**，
    而且它把结论写歪了（「TEA 与 INT 两端互换」→ 错写成「SOC 反过来」）。
    ⇒ **表格的同名行是抄串的高危区**；核对要**逐字段**，不能抽查。

20. 🔴 **「静默跳过的过滤器」和「写死的记录字段」会合谋 —— 单看哪一边都正常。**
    `g1_c_analyze.py` 在 C 只剩 2/14 个 adapter 时差点被跑出个半截产物。查下去发现三层：

    ```python
    d = [... for s in SEEDS if ("own10", s) in f1 and ("mixnorm", s) in f1]  # ① 静默丢弃
    d.mean(); d.std(ddof=1); d.std(ddof=1)/np.sqrt(len(d))                   # ② 全都自动适应
    res = {"set": args.set, "seeds": SEEDS}                                  # ③ 写死全 7 个
    ```
    ① 少一个种子不报错 ⇒ ② 统计量照算，n 从 7 变 6 谁也看不见 ⇒
    ③ **产物里仍写着 7 个种子**。净效果：一个**声称 7 个种子、实际算在 6 个上**的
    `g1_c_analyze_c.json`，形状与最终版**逐字节同型**，事后从产物无法分辨。

    ⇒ 与 §四.16 的区别值得分清：16 是**同一个页面内**写死常数挨着现算量、借它的可信度；
    本条是**写死的常数在产物里、静默的过滤器在代码里**，分居两处**合谋**。
    单独看代码那行「很常见」，单独看产物那字段「写得没错」。

    ⇒ 修法：把种子列表在**每一层都变成返回值**（`delta_by_seed` 返回 `seeds_used`；
    `report` 的 `n_seeds`/`f1` 键数都从它派生；`boot` 里加 assert 兜底），
    并在入口加**拒绝出数**的完整性闸（`assert_complete`，缺谁指名道姓；
    真要跑残缺集须显式 `--allow-partial`，产物记 `partial=true`）。
    **只报数、不设通过阈值**——阈值是拍的常数就会误事（§四.16）。

    ⇒ 代价是必须**实测**这道闸：先用 12/14 跑一次证明它拦住且**没写出任何文件**；
    再造一个「缺一条臂」的残缺输入，证明 `boot` 的 assert 真会炸（不是恒真自检）。

    ⇒ **家族扫描**：同型 `[f(s) for s in SEEDS if ... in ...]` 在 8 个脚本里共 12 处。
    但只有这一个把「静默过滤」和「写死记录」**配了对**；其余要么写的是**算出来的**
    `seeds`（安全，正是本次改成的形状），要么逐种子落成独立文件（缺了就是缺文件，看得见）。
    已入库的 `g1_c_analyze_e4c.json` 顶层 `seeds` 虽是旧脚本写死的、不可信，
    但其 `main.delta_by_seed` 长度 **= 7**、`f1` 键数 **= 14** ⇒ **确实是完整 7 种子，未受污染**。
    同族：跑批没跑完、恒真的自检、看不见的监控、会过时的判据常数。

21. 🔴 **同一个数据，换个仪器，答案差 6 倍 —— 而两个答案的汇总统计都长得很合理。**
    〔新，2026-09-23，DuplexGen 重叠测量〕问「`dialogue.wav` 里有多少时间双方同时出声」：

    | 仪器 | 判据 | 结果 |
    |---|---|---|
    | ① 每声道**自己的 Otsu 阈值** | 拍的（虽然是从数据里挑的） | 重叠 **0.17–1.74%** |
    | ② NCC 定时刻 + 对方声道**分位** | 零模型给的分位线 50 | **20/20** 的 backchannel 落在对方说话时 |
    | ③ **精确数字零**（样本 ≠ 0） | 无参数 | 重叠 **2.02–6.71%**，BC 窗口 87–95% 被覆盖 |

    ①**错得有道理**：Otsu 的分割点在「响亮语音 vs 静音」上，而 backchannel 是短的轻声，
    落在**它自己说话人**分布的第 34–86 分位 ⇒ **恰好被阈值漏掉**，
    于是"重叠"只剩轮次交接的碎渣。**阈值不是随便拍的，是认真挑的 —— 仍然错。**
    ⇒ 与 §四.6（阈值必须对零模型）互补：那条讲**线画在哪**，
    本条讲**有些量压根不该过阈值** —— 波形显示静止声道是**精确的 0.00000**，
    "有没有人"是**确定事实**，把它变成估计量就凭空造出了犯错的空间。

    ⇒ ② 的价值在于**零模型是白送的**：窗口随机摆放时，窗口内中位能量落在全段分布的
    分位数期望就是 **50**，于是判据线 = 50 而不是拍的数。20/20 高于 50%（中位 72.4）
    ⇒ 随机摆放下 P = 2⁻²⁰。

    ⇒ 过程中我**自己写错了两次**，两次的汇总统计都毫无异样：
    (a) 秒→帧下标左结合写成 `t0*sr/1000/HOP_MS`（差 24 倍，量的是早了 21 秒的窗口），
    输出全是 0.0%/74.9%/98.7% 这类合法百分位，**边界 assert 也拦不住**；
    (b) 拿「丢掉 <60 ms 段」的过滤器结果去算**总量**（15% vs 真值 94%）。
    ⇒ 纪律：**过滤器可以用于打印好看的段，绝不能用来算总量**；
    **逮住它们的是逐单元打原始量 + 两套独立仪器对同一件事给出矛盾答案**，
    不是任何汇总统计。同族：恒真的自检、看不见的监控、写死常数借走现算量的可信度。

22. 🔴 **「两条独立读数」可以是代数上同一个量 —— 于是预登记的预测注定失败（或注定通过）。**
    〔新，2026-09-23，§5.2c 预登记〕写「数字拼接」的 base rate 时定了三条主读数，第一条是

    ```python
    both     = (L != 0) & (R != 0)      # 双方同时出声
    one_zero = (~both).mean()           # 「主读数 1」：除重叠外总有一侧是数字零
    overlap  = both.mean()              # 「主读数 2」
    ```

    **`one_zero ≡ 1 − overlap`。** 于是 P1(`one_zero ≥ 99%`) ⟺ P2(`overlap ≤ 1%`)，
    两条号称独立的读数**不可能一真一假**；而 P2 预测的中位重叠是百分之几
    ⇒ **P1 在被写死的那一刻就注定失败**。冒烟一跑果然报"未达 2.4%"。

    ⇒ 与老账 `permutation-test-covers-one-variance-source`（「三个独立检验支持
    可能只是同一个盲区」）**同族但形态是新的**：那条讲几个检验**共享一个盲区**
    （所以一致不构成证据）；本条讲两个读数**根本就是同一个量**
    （所以一致是恒真的、分歧是不可能的）—— 连"独立"的资格都没有。

    ⇒ **预登记特有的纪律**：写完预测后，**逐条验算它们之间有没有代数关系**
    （这里 `a + b = 1` 一眼可见，但当时没验）。同族：恒真自检、写死常数借走现算量的可信度。

    ⇒ 有意思的是**逮住它的是冒烟，不是全量**：小样本先跑一次的价值不只是省时间，
    它会把"注定失败"的预测在花大成本之前顶出来。

    ⇒ 更正后的 P1' 要**另找与被检量无关的量**：问的是"静止声道是不是精确的零"
    （有没有混响/串音/本底噪声），就量**每声道精确零的样本占比**、
    **有声样本中 < −60 dBFS 的比例**、**最小非零幅度 vs 量化步长** —— 这三条都不含 `overlap`。
    更正**写于看到 165 条冒烟之后**，所以在文档里**标明是事后更正、不是预登记**。

23. 🔴 **打平的 `argmax` 会把「无法判定」读成一个**具体的类别**。**
    〔新，2026-09-23，§5.2d〕§5.2 写下的句子是「`utterances/NN.wav` 的声道占用**严格交替**
    （`0=L, 1=R, 2=L, …`，20/20 无例外）」。代码长这样：

    ```python
    k = int(np.argmax([ncc(x, L), ncc(x, R)]))   # 0 ⇒ 判成 L
    ```

    有些 utterance 在**两个声道上都全零**（它们其实是「对方说话」的那些 turn，
    内容在**另一路**上）⇒ 两条候选得分**同为 0**，`argmax` 取下标 **0**
    ⇒ **「无法判定」被静默读成「匹配 L」**。

    ⇒ 这与 §四.21（**仪器选错**：量错了量）是**同族但形态不同**：那里是问错了问题，
    这里是**代码回答了一个没人问的问题，而且每次都给出一个合法答案**。
    20/20「无例外」不是 20 次确证，是 **20 次同一个默认值** —— 一致性本身被当成了证据。

    ⇒ 纪律：**打平不是数据，是代码在替你选**。凡 `argmax`/`argmin`/排序取首个当分类器，
    都要问「两条打平时返回什么，那个返回值的含义是什么」；
    更稳的是**让打平显式变成第三个类别**（本处即 `both_zero`），而不是让它掉进下标 0。

    ⇒ 逮住它的是**换仪器重做**（§5.2d 用精确样本相等定址），不是任何汇总统计 ——
    输出列里全是 `L`，每一行都是合法值，汇总看不出任何异常。

24. 🔴 **结论对、理由错：一个被证伪的论证撑着一个被证实的结论 —— 必须重证结论，不许只换理由。**
    〔新，2026-09-23，§5.2d〕§5.2 的结论是「L 恒为边听边给反馈的一方，backchannel 永远
    在对方说话时由 L 发出」。它的**论证**是「带 BC 的 utterance 全是奇数 = 全是 R」
    —— 该论证**是 §四.23 的伪影**，而且在 6 条探针对话里**就有 2 条反例**
    （PLN `MUL0015` 是 06/08/10/18、SOC `soda_train_10004` 是 00/02/06，**全是偶数**）。

    ⇒ 危险在于：**结论恰好是对的**。20/20 个 BC 确实逐样本精确落在 L 上、承载它的 turn
    主说话人确实都在 ch1。于是「把伪影拆掉」这一步很容易被偷懒成「把理由换掉、结论留着」——
    但那样你**永远分不清自己哪些结论是真站得住的**，因为论证与结论的**承重关系**没被检验过。
    ⇒ 纪律：**论证被证伪 ⇒ 结论降级为「待重证」，然后用一套独立仪器从头证一遍**（§5.2d 做了）。

    ⇒ 同族孪生（本项目内）：
    - 「先填表后核数」「结论先写、脚本后跑、方向正好相反」（老账 `hardcoded-conclusions-escape-reproduction`）
    - 「预测命中 ≠ 机制成立」（`prediction-hit-is-not-mechanism`）—— **同一个形状**：
      数对上了，不等于中间那条链子成立。本条是它在**论证**层的实例：
      结论对上了，不等于**理由**成立。

    ⇒ 顺带一条纪律：**「20/20 无例外」这种一致性陈述，先问它有没有可能是同一个默认值**
    （§四.23）再当证据用。

25. 🔴 **同一个容器里两个字段都读得像你要找的东西 —— 选错的那个会给出一个「像结果」的坏数。**
    〔新，2026-09-23 晚，§3.6〕`duplexgen-spoken` 的每个 `meta.json` 里：

    | 字段 | 长度 | 是什么 |
    |---|---|---|
    | `utterances` | = `num_turns`（首条 32） | 按**话轮**切 |
    | `speech_meta` | 20 | 按**语段**切，与 corpus `history` 等长 |

    拿 `speech_meta` 比 corpus：**98.6%**。拿 `utterances` 比：**13.8%**。

    ⇒ 危险不在"错"，在于**它错得像个部分成功**：13.8% 不是 0，
    读起来像「有一部分对得上」而不是「你选错了字段」。
    与 §3.1 那个 **12.2%** 的「`word_index` 索引撞号」是**同一个形状** ——
    一个 12–14%、看着像结果的数，其实是仪器用错了。
    与 §四.23（打平的 `argmax` 读成具体类别）**同族**：都是
    **代码替你在两个候选里选了一个，而返回值每一行都合法**。

    ⇒ 我第一次做这个 join 正是拿 `utterances` 比的，得到「0/16 对不上」，
    **差一点把 §3 那条错误结论又"独立复现"了一遍** ——
    第二次"独立验证"如果用的是同一个错误的仪器，它只是把错误坐实。

    ⇒ 纪律：**同一个文件里出现两个都像目标物的字段时，把两个都算出来并列打印**，
    不要只报你选的那个（§3.6 的 K4 就是这条纪律的产物）。
    与 §四.14（join 键命中 100% 而实体同一 0%）合起来是一条完整的 join 纪律：
    **键要验实体同一，字段要验选了哪个。**

    ⇒ **孪生面：过滤器会制造缺口。**同一次测量里我按 `variant=="var00"` 筛，
    得到「只有 25/50 被标注 id 有 spoken」；按「任意变体」算是 **45/50**。
    `work_0502` 之类**根本没有 var00**。缺口是我的筛选造出来的，
    不是数据的 —— 与 `tiebreak-default-read-as-evidence` 里
    「一致性可能是我的代码在替我选」是同一个问句的两头。
