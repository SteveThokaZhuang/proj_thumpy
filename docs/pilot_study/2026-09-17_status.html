3G1 消融与那个被推翻的头条

3.1 实验设计

同一批数据、同样 7 个随机种子，只改观测的构造方式：

  • own10 —— 只喂自己的声道
  • mixnorm —— 两个声道各自电平对齐后相加

3.2 原结论

已作废

mixnorm 跨种子方差是 own10 的 18.6 倍（F=18.64, p=0.0026）—— G1 里唯一经得起分布无关检验的结论

该结论来自 E2 评估集（1600 块 / 1640 事件）： SD(mixnorm) = 0.1020 vs SD(own10) = 0.0236， 方差比 F(6,6) = 18.67，置换 p = 0.0026。 它一度被当成主要发现。

3.3 推翻它的证据

把同一批已训好的 adapter（没有重训，纯读盘）拿到 自然流行率的旧 300 块集上评：

两套评估集上的方差对比
评估集真值正例率 corr(报的比例, F1) own10mixnorm SD(mixnorm)SD(own10)F
旧 300（自然流行率） 0.06 +0.471 −0.122 0.0183 0.0234 0.62
E2（事件密集） 1.00 +0.503 +0.935 0.1020 0.0236 18.67

两处关键事实：

  1. own10 的 SD 在两套集上几乎一模一样（0.0234 vs 0.0236）—— 所以这不是「旧集更吵」，而是臂 × 评估集的交互：变的是 mixnorm，不是评估难度。
  2. 方差排序在自然流行率集上反转（F=0.62，即 mixnorm 反而更稳）。

3.4 机制

E2 是「事件密集」集：1640 事件 / 1600 块，100% 的块都有 GT 正例，一个负例都没有。 在这种集上： 

多报 → 只增加 TP，几乎不增加 FP → F1 随开火率单调上升

而 P1 已经测出 mixnorm 的各种子把决策边界画在了不同地方（见 §5）。 于是「阈值方差」在 E2 上被原样放大成 F1 的种子间方差。 自然流行率集上多报会被 FP 惩罚，corr(报的比例, F1) 从 +0.935 崩到 −0.122， 放大通道消失，方差随之回落。

2026-09-17 晚补充（Q5）· 放大发生在哪一层，现在测清楚了

把同一批 adapter 的 margin 探针跑到自然流行率集上后发现， 各种子平均 margin 的 SD 几乎不动： own10 0.183 → 0.180，mixnorm 0.525 → 0.546。 也就是说阈值离散本身与评估集无关，它是模型的性质。 变的只是「阈值离散 → F1 离散」这个映射： E2 上没有负例，映射接近恒等；自然集上多报要吃 FP，映射被压平。 所以上面说的「放大通道」是映射层面的，不是 margin 层面的 —— 这也解释了为什么 §7.2 里扩集救不了 F1 那件事。

附带的方法论教训

E2 的正例率是 1.00，所以块级 AUC 在这套集上根本无法定义（没有负例）。 当时报的 AUC=nan 不是代码错，是评估集的性质。 一个 100% 正例的集合没法测判别力，只能测操作点。

7.1 Q1：排除法做到了「交互」

三个候选：(a) 数据顺序 / shuffle、(b) LoRA 初值、(c) 两声道相加的增益不确定性。

先扣掉 (a) 和 (b)。 scripts/ari_g1_seed_recon.py 直接读 training_args.bin 与 adapter_model.safetensors：

  • 全部 14 个 run 的 data_seed = None（且 full_determinism = False） ⇒ transformers 的样本顺序由 seed 派生，同 seed ⇒ 同数据顺序。
  • 同 seed 跨臂的 lora_A 相对差 = 0.111； 而跨 seed 同臂 = 1.414 = √2 （两个独立随机向量的期望相对距离 —— 正是「初值本来就不同」时的取值）。

于是同 seed 的 own10 / mixnorm 是一对「同初值 + 同数据顺序 + 同超参， 唯一差异是音频」的干净对照。对每一对而言，种子带来的 (a)(b) 都被扣掉了， 它们不可能是两臂之间差异的来源。

配对检验：音频不是系统性偏移。

每种子平均 margin 的配对差 d = mixnorm − own10
  = −0.0689 ± 0.4828,   t(6) = −0.38,   精确置换 p = 0.703
逐种子 d: −0.535  +0.285  −0.432  −0.152  −0.010  +0.809  −0.446

均值不显著 —— 音频不系统性地把阈值推高或推低。 但 d 本身的离散很大（SD 0.483），而 own10 整体跨种子 SD 只有 0.183。 同一个音频操纵，在不同的种子上给出方向不同、幅度不同的阈值移动。 这就是「交互」。

方差分解（scripts/ari_g1_threshold_source.py）：

以两臂平均方差 0.1546 为分母:
  种子层 Var(s)   = 0.0963   62.3%      s = (m+o)/2
  音频层 Var(d)/4 = 0.0582   37.7%      d = m−o

更正：早先一版按 Var(mixnorm) 做分母，得出 「34.9% / 21.1% / 44% 协方差」。那个 44% 的「协方差」是代数恒等式 Cov(s,d) ≡ (Var(m)−Var(o))/2，只是「两臂方差不同」的改写，不是独立发现。 换成平均方差做分母后两项之和正好 100%。

SD 比本身通过了显著性检验（scripts/ari_g1_margin_sd_test.py）。 这一步是必须的 —— 「2.9 倍」同样是从 7 个点估出来的 SD， 正是 §3 那次翻车的同一类操作： 

F(6,6) = 8.276   (SD 比 2.88x)
精确置换 p (200k 次, 14 个值随机分 7/7) = 0.0160
F 分布 95% 临界值 F(6,6) = 5.820   -> 超过
留一: 去掉 seed 31337 时 p = 0.0790 (掉出 0.05); 其余 6 个保持显著

7.2 Q2：ΔF1 ≈ +0.034 —— 比「弱显著」更弱，站不住

§3.5 报的配对 ΔF1 = +0.0340 ± 0.0309，n=7，精确置换 p = 0.0469。 四条独立线索都说这个数比它看起来更弱：

① 它落在检验的分辨率边缘。 n=7 的符号翻转检验只有 2⁷ = 128 个符号模式， 两尾最小可能 p = 2/128 = 0.0156。观测 p = 0.0469 恰好是 6/128 —— 已经在尾部，但那个尾部只有 6 个原子。

② 留一：去掉 7 个种子里 6 个都会掉出 0.05。

去掉 42 / 1234 / 7 / 3407 / 31337   ->  p = 0.0938
去掉 2024                            ->  p = 0.0625
去掉 55555（唯一反向的那个）         ->  p = 0.0312

③ 符号检验（只看方向不看大小）6/7 → p = 0.125。

④ 决定性的一条：置换检验低估了不确定度。 置换检验只让种子随机，把 300 块 / 20 个事件当成固定的。 而「站得住吗」隐含的是能否推广到别的块，那就必须算上块抽样。 块级 bootstrap（7 个种子共用同一份重抽块）： 

SE_seed  = 0.0117   <- 置换检验实际用的那个
SE_chunk = 0.0198   <- 置换检验没有算的那个, 而且更大
合成 SE  = 0.0230
t = 0.0340 / 0.0230 = 1.48        (而不是只看种子时的 2.91)

7 个种子评的是同一批块，所以「换一批块会怎样」在所有种子间是共有的偏移， 在 across-seed SD 里被约掉了 —— 只按种子做置换检验会系统性低估真实不确定度。

结论

ΔF1 = +0.034 目前判不住。 方向一致（6/7），但 p=0.0469 是乐观口径、 算上块抽样后 t = 1.48、留一去掉任意一个同向种子就掉出 0.05。 §3.5 里「弱但可复现」的说法应降级为「方向一致，但未达可判定」。

「扩集能不能救」—— 先算，再决定要不要花那 19 小时。 scripts/ari_g1_eval_power.py 把两个随机来源分开外推： 

Var(种子)   = 1.366e-04   —— 不随事件数缩小 (它是模型的性质)
Var(块抽样) = 3.939e-04   —— 按 1/k 缩

  事件数   块数   GPU小时     SE       t
     20    300      1.9    0.0230   1.48     <- 现在
     40    600      3.9    0.0183   1.86
     80   1200      7.8    0.0153   2.22
    160   2400     15.5    0.0136   2.50
    320   4800     31.1    0.0127   2.68
  k->∞            ∞       0.0117   2.91     <- 天花板

天花板就是现在这个 t。 扩集不能把这个效应变显著 —— 它只能把现在这个「乐观的 p=0.0469」变成「名副其实的 p=0.0469」， 因为种子那一项根本不随事件数缩。

唯一能改判的是一件事：种子 55555 那个 −0.0345 到底是真反向还是噪声。 扩集正好能回答它 —— 若翻正，7/7 同向，两尾 p 触及 n=7 的下限 0.0156； 若它稳稳地负，这个结论就该被放弃。 这是一个「确认或否决」实验，不是「跑出显著性」实验。

7.3 Q5：margin 探针跑上了自然流行率集 —— §3.4 闭环，但机制位置要改写

对同一批 14 个 adapter（没有重训）在旧 300 块自然流行率集上重跑 margin 探针 （scripts/g1_margin_natural.sh → ari_g1_margin_natural.py， 输出 g1_margin_nat_*.json）。

① §3.4 的预言部分成立：跨 0 率确实回落。

armE2（400 块）自然集（300 块）变化

mixnorm 回落得更多，但没有收敛到 own10 —— 差距从 26 pt 缩到 17 pt 仍在。 所以「E2 把跨 0 放大」是真的，但跨 0 率本身不是全部。

② 更重要的一条：阈值离散与评估集无关。

arm各种子平均 margin 的 SD（E2）自然集变化

这和 §3.3 里 F1 的表现（own10 的 SD 两套集都是 0.0234 / 0.0236）是同一个形状： 变的是 mixnorm 与评估集的交互，而 mixnorm 的阈值离散本身是模型的性质， 换评估集不动它（比值 2.88× → 3.04×）。

所以要改写 §3.4

放大通道发生在映射层面，不在 margin 层面： E2 上没有负例，「阈值离散 → F1 离散」接近恒等；自然集上多报要吃 FP，映射被压平。

③ 顺带把 §7.1 的候选 (c) 做成了可判定的检验。 g1_mix_check.json 的 300 个块号与自然集探针完全一致（交集 300/300）， 于是 gain 与 margin 可以逐块 join —— 这是 E2 上做不到的 （E2 与这份 gain 的块号交集为 0）。结果见 §7.1 最后一段。

探针把 margin 四舍五入到 4 位，自然集上有 50 个（块，种子）对的 margin 恰好是 0.000。 跨 0 的定义对 > 0 与 < 0 都要求严格，所以这些对两边都不算， 会让跨 0 率略微低估。占 2100 对里的 2.4%，不影响上面的比较。
